## Scope (one file, one line removal)

**Target file**: `scripts/audit/settings-version-check.sh`

**Bug**: Line 19 `trap 'exit 0' ERR` silently swallows ALL errors and exits 0,
defeating the script's documented exit-code contract:

> Exit codes:
>   0 — PASS (hashes match OR --init succeeded)
>   1 — FAIL (divergence detected; settings.json edited mid-session; restart required)
>   2 — SKIP (no baseline; first run) OR PROJECT_DIR/settings.json not found

With `set -uo pipefail` already in effect on line 18, an unset variable, broken
pipe, or `sha256_of_file` returning HASH_UNAVAILABLE causes the trap to fire,
returning exit 0 (PASS). The audit then falsely reports "settings unchanged"
when the script is actually broken — exactly the inverse of what we want.

**Fix**: Remove line 19 entirely (`trap 'exit 0' ERR`). Keep `set -uo pipefail`
on line 18 — that's the correct guard.

## Exact change

**Old** (line 18-20):
```bash
set -uo pipefail
trap 'exit 0' ERR

PROJECT_DIR="${CLAUDE_PROJECT_DIR:-$(cd "$(dirname "$0")/../.." && pwd)}"
```

**New** (line 18-19):
```bash
set -uo pipefail

PROJECT_DIR="${CLAUDE_PROJECT_DIR:-$(cd "$(dirname "$0")/../.." && pwd)}"
```

(One line deletion. No other changes anywhere in the file.)
