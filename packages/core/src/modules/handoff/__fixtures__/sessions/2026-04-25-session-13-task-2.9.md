## Decisions Made
- **auto-bundle vs targeted**: chose targeted whitelist (HTTP + Fastify + Pino) via
  `getNodeAutoInstrumentations` with explicit `enabled: false` on 15+ others. R1
  mitigation: avoids fs/dns/net/mongo spans in tests. Rationale in tracing-bootstrap.ts.
- **R4 singleton pattern**: `const sdkHolder = { sdk: null }` instead of `let _sdk`
  preserves I-14 (no module-level let) while enabling mutation.
- **Web UI**: ActivityPage already stored `trace_id` on ActivityEntry and rendered it
  in the list. No code change needed — just added tests to verify the existing behavior.
- **Carryover Task 1.14 OTEL E2E**: the integration test `tracing-http-propagation.
  integration.spec.ts` tests A `(parent-child span linkage)` and B `(I-9 trace_id in
  all log lines)` which are the Phase 1 carryover items. The full-lifecycle.spec.ts
  OTEL assertion remains scoped (no regression).
