## Goal (verifiable outcome)

Given a session that ended with `reason: CONTEXT_FULL`, produce a structured
`HandoffContext` DTO and a rendered plain-text prompt (≤ 5000 tokens, ~20K
chars) suitable to seed the next Claude Code session's first user message.
The prompt must be derived **deterministically** from:

- **L0**: `git diff --stat` between the session-start commit and session-end
  HEAD (file-level change inventory).
- **L1**: parsed `agent-workspace/memory/sessions/YYYY-MM-DD-session-N.md`
  markdown extracted into completed tasks, pending tasks, decisions, and
  the explicit "Next Session Pickup" block.

No LLM calls anywhere (per decision 006). No network I/O. The only side
effects are file reads and a single `git` subprocess.

```ts
// types.ts

/** L0 file diff record. Pure data, no behavior. */
export interface FileDiffRecord {
  readonly path: string;
  readonly insertions: number;
  readonly deletions: number;
  /** True if `git diff` flagged the path as binary (no line counts). */
  readonly binary: boolean;
}

/** L0 summary returned by GitDiffCollector. */
export interface GitDiffSummary {
  readonly fromRef: string;          // session-start commit SHA
  readonly toRef: string;            // session-end HEAD SHA
  readonly files: readonly FileDiffRecord[];
  readonly totalInsertions: number;
  readonly totalDeletions: number;
  /** True if `git` could not run (e.g., not a repo). Render fallback expected. */
  readonly degraded: boolean;
  readonly degradedReason?: string;
}

/** L1 task record extracted from session log. */
export interface SessionTaskRecord {
  readonly title: string;
  /** Verbatim list-item body after the leading bullet, trimmed. */
  readonly detail: string;
}

/** L1 decision record. */
export interface SessionDecisionRecord {
  readonly id?: string;              // e.g., "001" if heading is "### Decision 001 — ..."
  readonly title: string;
  readonly detail: string;
}

/** L1 parsed session log. */
export interface SessionLogSummary {
  readonly filePath: string;
  readonly sessionDate?: string;     // YYYY-MM-DD if parseable from filename
  readonly sessionNumber?: number;   // N if filename matches /session-(\d+)/
  readonly completed: readonly SessionTaskRecord[];
  readonly pending: readonly SessionTaskRecord[];
  readonly decisions: readonly SessionDecisionRecord[];
  /** Verbatim text of the "Next Session Pickup" section, if present. */
  readonly nextSessionPickup: string | null;
  /** Diagnostic flags surfaced to renderer. */
  readonly missingSections: readonly (
    | 'completed' | 'pending' | 'decisions' | 'next_session_pickup'
  )[];
}

/** Top-level DTO assembled by HandoffContextBuilder. */
export interface HandoffContext {
  readonly sessionId: string;
  readonly projectId: string;
  readonly endedAt: string;          // ISO-8601
  readonly endedReason: 'CONTEXT_FULL' | 'CONTEXT_FULL_FORCED' | 'OPERATOR' | 'ERROR';
  readonly gitDiff: GitDiffSummary;
  readonly logSummary: SessionLogSummary | null;  // null if log file absent
  readonly degraded: boolean;
  readonly degradedReasons: readonly string[];
}

/** Renderer output. */
export interface RenderedPrompt {
  readonly text: string;
  /** Char-based proxy for tokens — see A.6. */
  readonly tokens: number;
  readonly truncated: boolean;
  readonly truncationActions: readonly TruncationAction[];
}

export type TruncationAction =
  | { kind: 'dropped_oldest_decisions'; count: number }
  | { kind: 'dropped_oldest_completed'; count: number }
  | { kind: 'dropped_diff_records'; count: number }
  | { kind: 'shortened_pickup'; charsRemoved: number };

/** Domain errors (extend existing DomainError pattern). */
export class HandoffBuilderError extends Error {
  readonly code:
    | 'GIT_NOT_AVAILABLE'
    | 'GIT_BAD_REVISION'
    | 'LOG_READ_FAILED'
    | 'LOG_TOO_LARGE'
    | 'INVARIANT_VIOLATED';
  readonly cause?: unknown;
  constructor(code: HandoffBuilderError['code'], message: string, cause?: unknown);
}
```

> No `any` in any signature. Every field is `readonly`. Discriminated union
> on `TruncationAction.kind` so renderer telemetry is statically exhaustive.

## A.4 Regex shape table for L1 (session-log-parser.ts)

The parser is deterministic regex/state-machine. No fuzzy matching. Patterns:

| Construct | Pattern (anchored) | Notes |
|---|---|---|
| Section heading | `^##\s+(?<title>[^\n]+?)\s*$` | H2 only. H3 within section is treated as sub-heading and ignored unless it's a decision (see Decisions row). |
| Completed section detection | heading title matches `/^(Accomplished\|What Got Done\|Completed)\b/i` | Multiple aliases — real logs use all three. |
| Pending section detection | heading title matches `/^(Pending\|Outstanding\|To[- ]Do\|Remaining)\b/i` | |
| Decisions section detection | heading title matches `/^Decisions(\s+Made)?\b/i` | |
| Next-pickup section | heading title matches `/^Next\s+Session\s+Pickup\b/i` | Verbatim body capture until next `^##` or EOF. |
| List item | `^[-*]\s+(?<body>.+?)$` (multi-line: continuation lines start with `^\s{2,}`) | First line = title (truncate at `:` or `—` if present), full body = detail. |
| Decision sub-heading | `^###\s+Decision\s+(?<id>\d+)\s*[—-]\s*(?<title>.+?)$` | Inside decisions section, captures id + title. Following paragraphs until next `^###` or `^##` form detail. |
| Code fence | `^```` (start) ... matching `^```` (end) | Lines between fences are skipped entirely — preserves binary blobs / shell snippets. |
| HTML comment | `<!--` ... `-->` | Stripped before parsing. |

State machine: scan line-by-line, track `(currentSection, inFence)`. List
items are accumulated into the current section's bucket. Unknown sections
are dropped. Section heading `## Foo` resets bucket.

**Drift tolerance** (per phase plan L138, L149):
- Missing section → empty array, flag pushed to `missingSections`. Never throw.
- Heading at H1 (`# Foo`) instead of H2 → ignored (top-of-file title is always H1).
- Heading with trailing colon (`## Decisions:`) → matched (regex strips trailing `:`).
- Subtask vs. task wording variation absorbed into list-item parser; we don't
  classify, we just capture verbatim.

## A.5 Truncation order in renderer (prompt-renderer.ts)

Renderer assembles in a fixed section order:

1. Header (sessionId, endedAt, endedReason) — **never truncated**
2. Next Session Pickup block (verbatim from log) — **shortened last** (most important)
3. Pending tasks — **never dropped, may be elided per-item**
4. Decisions (newest first) — droppable
5. Completed tasks (newest first) — droppable
6. Git diff stat (top N files by `insertions+deletions`) — droppable

If `tokens > HANDOFF_MAX_TOKENS`, apply truncation in this order until under cap:

1. **Drop oldest decisions** in 25%-of-list increments until none remain or under cap.
2. **Drop oldest completed tasks** in 25% increments until none remain or under cap.
3. **Drop tail of git diff records** in 25% increments (keep top contributors).
4. **Shorten Next Session Pickup** block by truncating to 2000 chars + `…[truncated]`.
5. If still over cap → emit warning log, hard-truncate text to `HANDOFF_MAX_CHARS` and
   set `truncated: true` with a final `kind: 'shortened_pickup'` action recording
   chars removed.

**Pending tasks are NEVER dropped.** Rationale: pending = future work; losing
it loses charter F4 value. If pending alone exceeds the cap (pathological log),
we hard-truncate at char boundary rather than dropping records — operator
sees `…[truncated]` and reads the source log themselves. Logged at WARN.

Each truncation step appends a `TruncationAction` to the result so observability
sees what was lost.

## A.6 Token-cap rationale

We do **not** use a real tokenizer (`tiktoken`, `@anthropic-ai/tokenizer`) for
two reasons:
1. Adds a dependency that has historically pulled WASM/native binaries.
2. Karpathy P2 — char-based proxy is good enough for a soft budget on
   markdown ASCII content. The 4-chars-per-token estimate is the
   industry-standard rule for English; we're under-estimating slightly for
   safety which is the correct direction (we'll send fewer tokens than the
   cap, never more).

The hard char cap `HANDOFF_MAX_CHARS = 20000` is the actual enforcement.
The `tokens` field in `RenderedPrompt` is `Math.ceil(text.length / 4)` —
purely informational for telemetry / OTEL attribute.

# Part C — Risks & Mitigations

| ID | Risk | Severity | Mitigation |
|---|---|---|---|
| R-A | Log-format drift across template versions | HIGH | Parser tolerates missing sections (B.2 fixtures); never throws on missing/malformed; `missingSections` flag surfaces drift to telemetry. Aliases for section headings (Accomplished/Completed/What Got Done). |
| R-B | Git binary mode + Windows CRLF in `git diff --stat` output | MEDIUM | 3.5.b strips `\r` before parsing; binary files explicitly handled (B.3 `binary-diff.txt`). Hard-coded `git -C <path>` so cwd quirks on Windows don't matter. |
| R-C | Truncation correctness — operator-critical info dropped | MEDIUM | Truncation order is pre-authorised in A.5; pending tasks are never dropped; T-CAP-2..3 enforce. Each truncation logged in `truncationActions` for audit. |
| R-D | Performance on huge logs | LOW | 256KB hard cap (LOG_TOO_LARGE); `huge-50kb.md` fixture asserts < 100ms in 3.5.c. |
| R-E | Implementer rationalises an LLM call ("just for polish") | HIGH (charter-breaking) | Decision 006 binding; 3.5.a/b/c/d/e implementers must read it before starting. Lint rule + test gate + verifier grep are three layered guards. |
| R-F | execa dependency surface — `git` binary not installed on operator's machine | LOW (degrade, not fail) | `GitDiffCollector.collect` returns `degraded: true` rather than throwing. Renderer omits the diff section gracefully. |
| R-G | Token-cap proxy under-/over-counts on non-ASCII (Chinese, emoji) | LOW | Acceptable per A.6 — proxy under-counts for non-ASCII (more conservative); operator never gets a too-large prompt. |

## 3.5.b — L0 git-diff collector via execa (~25K tokens)

**Goal**: `GitDiffCollector.collect(repoPath, fromRef, toRef)` returns
`GitDiffSummary` from `git diff --stat <fromRef>..<toRef>`.

**Files**:
- `packages/core/src/modules/handoff/git-diff-collector.ts` — implementation (~120 LOC).
- `packages/core/src/modules/handoff/git-diff-collector.spec.ts` — ≥6 tests (one per B.3 fixture row).
- `packages/core/src/modules/handoff/__fixtures__/git-diff/{clean,binary,empty,crlf,bad-revision,git-not-found}.txt` — 6 fixture files.

**Implementation contract**:
- Hard-coded binary `'git'` (no user input). `cwd: repoPath`. `timeout: 5000`. `reject: false`.
- Args: `['-C', repoPath, 'diff', '--stat', `${fromRef}..${toRef}`]`.
- Parse stdout line-by-line; expected line shape: ` <path> | <total> {+++,---}` and ` <path> | Bin <a> -> <b> bytes`.
- Last line: ` N files changed, X insertions(+), Y deletions(-)` — used for sanity-check, not authoritative.
- On non-zero exit OR `failed`: `degraded: true`, `degradedReason: stderr.split('\n')[0] || 'git failed'`.
- On `ENOENT`: catch in execa wrapper, return `degraded: true, degradedReason: 'git not available'`.

**Test count**: 6 (one per fixture) + 1 timeout test using a fake execa that resolves after 5001ms. Total 7.
**Risks**: B.3 `crlf-diff.txt` is the Windows compatibility check. Strip `\r` before parsing.
**Reviewer focus**: never throws; binary string `'git'` is a literal; timeout is wired; CRLF stripped; degraded path covers all three failure modes (non-zero exit, bad revision, ENOENT).

## 3.5.c — L1 session-log markdown parser (~40K tokens — biggest)

**Goal**: `SessionLogParser.parse(filePath)` returns `SessionLogSummary`
extracted via the regex/state-machine in A.4.

**Files**:
- `packages/core/src/modules/handoff/session-log-parser.ts` — implementation (~250 LOC).
- `packages/core/src/modules/handoff/session-log-parser.spec.ts` — ≥10 tests.
- `packages/core/src/modules/handoff/__fixtures__/sessions/*.md` — 5 real log copies (B.1).
- `packages/core/src/modules/handoff/__fixtures__/sessions/synthetic/*.md` — 8 hand-authored edge fixtures (B.2).
- `packages/core/src/modules/handoff/__fixtures__/sessions/expectations.json` — golden expectations file.

**Implementation contract**:
- Read file with `fs.promises.readFile(filePath, 'utf-8')`. Throws `LOG_READ_FAILED` on ENOENT/permission.
- Stat-check for size > 256KB → `LOG_TOO_LARGE`.
- Normalise `\r\n` → `\n`.
- Strip HTML comments before scanning.
- State machine: `currentSection`, `inFence`, `fenceMarker`. On `^```` or `^~~~`, toggle fence (record marker; only matching marker closes).
- Inside section, accumulate list items per A.4 list-item regex. Continuation lines (`^\s{2,}`) append to previous item's detail.
- Decisions section: scan for `^### Decision (\d+) — (title)$` sub-headings; capture detail until next `^###` or `^##`. If no sub-headings present, fall back to list-item parsing.
- "Next Session Pickup": capture verbatim from line after heading until next `^##` or EOF. Trim trailing whitespace.
- Filename parsing: regex `(\d{4}-\d{2}-\d{2})-session-(\d+)` from basename → `sessionDate` + `sessionNumber`. Both optional.

**Test count**: 5 golden (B.1) + 8 synthetic (B.2) = 13. Performance assertion on `huge-50kb.md` < 100ms.
**Risks**:
- R-A (drift): primary risk. Aliases handled. Reviewer must verify all 3 alias spellings of "completed" section detected.
- R-D (perf): 256KB cap is the safety net.
- Encoding: utf-8 only. No BOM handling — BOM-stripped via simple `if (text.charCodeAt(0) === 0xFEFF) text = text.slice(1)`.

**Reviewer focus**: Part A.4 regex table matched verbatim; tolerance gates pass (every synthetic fixture parses without throw); golden expectations match.

## 3.5.d — Prompt renderer with token cap and truncation (~25K tokens)

**Goal**: `PromptRenderer.render(ctx, maxTokens?)` produces deterministic
plain-text + token count + truncation telemetry per A.5.

**Files**:

- `packages/core/src/modules/handoff/prompt-renderer.spec.ts` — ≥6 tests including T-CAP-1..6.

**Implementation contract**:

**Test count**: 6 (T-CAP-1..6 from B.4).

**Reviewer focus**: A.5 order matches; pending never dropped; deterministic output (call render twice with same input → byte-identical output); telemetry actions match what was actually done.
