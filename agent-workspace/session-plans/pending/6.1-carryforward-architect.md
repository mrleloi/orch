### 6.1.2 — INV-S9 Hook Latency Fix

#### Part A — Goal

Make `scripts/hooks/component-telemetry.sh` return to Claude Code in
≤ 50ms p99 / ≤ 20ms p50 for the synchronous portion, while preserving
exact JSONL output semantics (same fields, same dedup rule, same rotation

**Concurrency safety on JSONL append (new race risk):**

- The race risk flagged in phase-6-v2.1-absorption.md §8 row 1 is real:
  multiple background subshells may simultaneously call `append_with_rotation`
  → interleaved JSONL bytes.
- **Decision (autonomously resolved per ORCH_SPAWNED + Decision 014/Stop precedent**:
  do NOT use `flock`. Existing Orch precedent in `scripts/hooks/autonomous-stop-watchdog.sh:120`
  ("no flock() — not portable to Windows bash") and 5.1.3 architect §469
  ("do NOT add `flock` (file locking is not portable to Windows...)"). Adding
  `flock` would regress the cross-platform invariant.
- **Mitigation**: rely on POSIX `>>` append-atomicity for writes ≤ PIPE_BUF
  (4096 bytes per POSIX.1; Linux has 4096; Windows MSYS2 inherits the kernel
  guarantee). Each JSONL line is a single `printf '%s\n' "$json_line"` → the
  longest line in 1938 lines on disk is ≈ 480 bytes, well under 4096. The
  existing single `printf` invocation already satisfies append-atomicity
  per-line; multiple concurrent `printf >>` calls each emit a complete line
  without interleaving. **No flock needed.** Rotation (the one operation
  that is NOT atomic — `mv`-shift sequence at lines 317-323) becomes
  best-effort: the rare collision of two rotations would lose one in-flight
  line. Acceptable per JSONL-as-best-effort design (see 5.4.9 mailbox
  precedent). Document this rationale in a single-line comment above
  `append_with_rotation`.

**Required new comment (above `append_with_rotation`, ~line 304):**

```sh
# Concurrent-safety note: relies on POSIX >> append-atomicity per line
# (each line ≤ 480 bytes ≤ PIPE_BUF=4096). Rotation is best-effort; rare
# concurrent rotation may lose one in-flight line (acceptable per
# JSONL-as-best-effort design; precedent: mailbox count-idempotency 5.4.9).
# Do NOT add flock — Windows Git Bash portability invariant (precedent:
# autonomous-stop-watchdog.sh:120, 5.1.3 architect §469).
```
