**Result: 13 of 14 rows are MISSING under the naive Decision 024 resolution map.**

**Root cause analysis**: The `hook::` entries in the rollup represent Claude Code built-in tool event types (Bash, Read, Write, etc. — the Claude Code tool names that fire PreToolUse/PostToolUse hooks). These are not custom shell scripts. The Decision 024 map `hook::<name>` → `scripts/hooks/<name>.sh` was designed for custom hook scripts (e.g., `hook::component-telemetry` → `scripts/hooks/component-telemetry.sh`), not for built-in tool event types.

Similarly, `agent::unknown-agent` is a data-capture artifact (per Decision 025 §Signal quality assessment: "unknown-agent is an artifact of the SubagentStop hook not capturing agent identifiers"). It is not a named agent in `.claude/agents/`.

**Proposed handling (binding for 7.4.2 IMPL)**:

The linter MUST implement a two-tier resolution strategy:

**Tier 1 — Registered-component check**: Apply Decision 024 map. If resolved file exists → PASS.

**Tier 2 — Known-builtin exemption**: If the component_type is `hook` AND the component_name matches a known Claude Code built-in tool event name (capitalized: Bash, Read, Write, Edit, Grep, Glob, Agent, Task, TaskUpdate, TaskCreate, TaskRead, TaskWrite, SessionStart, SessionEnd, ToolSearch, ToolSearch, Skill, Stop, PreToolUse, PostToolUse) → mark as EXEMPT (not a missing-component violation; it is a runtime event type, not a registered script).

**Tier 3 — Known-sentinel exemption**: If component_name matches a known sentinel value (`unknown-agent`, `unknown-command`, `unknown-skill`) → mark as EXEMPT_SENTINEL with informational note.

**Exit code semantics (revised per this finding)**:
- Exit 0: all rows are PASS or EXEMPT or EXEMPT_SENTINEL
- Exit non-zero: at least one row is FAIL (registered component claimed but file not found)
- Informational-only: EXEMPT rows are printed if `--verbose` flag set (default: silent on EXEMPT)

**Impact on SC-35 gate** (phase master plan §7.4 Part C gate 2):
> `pnpm tsx scripts/utilities/citation-linter.ts --rollup agent-workspace/memory/component-rollup-phase-6.md` exits 0 (Phase 6 rollup is presumed clean — verify; if not, this becomes the linter's first real signal).

With the two-tier strategy: the Phase 6 rollup exits 0 (all 14 rows are EXEMPT or EXEMPT_SENTINEL — no registered custom components are claimed but absent). The gate holds. SC-35 closes.

**The linter's first real signal will fire when a rollup contains a row like `skill::new-skill-name` where `.claude/skills/new-skill-name/SKILL.md` does not exist** — which is exactly the intended hallucination guard.

5. If NOT exists AND SENTINEL_NAMES.has(name) → EXEMPT_SENTINEL
6. Otherwise → FAIL

This ordering means: if a `hook::component-telemetry` row appears, it resolves to `scripts/hooks/component-telemetry.sh`, which EXISTS → PASS (step 3). The EXEMPT path is only reached when the file does NOT exist. This is correct behavior.
