## Cross-Cutting Design Decisions (D&R log)

### DR1. Why 4 deliverables, not 3 (probe + test + audit + skill)

**Chosen**: 4. The Decision 035 §6 action items explicitly enumerate (a) the integration test, (b) the audit, (c) the skill update — that's three. The R-1 verification probe (Δ1) is mandated by Decision 035 §5 R-1 verification option (c) and is operationally inseparable from the IMPL leg; the implementer cannot author the observation md without already having dispatched a real Agent call during the substage. So Δ1 becomes a fourth deliverable rather than being implicit in master plan §11.5.2.

**Rationale**: explicit > implicit. Implementer must produce the artifact for 11.5.3's Decision 037 to cite R-1 evidence. If left implicit, 11.5.3 architect would have to ad-hoc construct the verdict from raw dispatch.jsonl — defeats the audit-trail-discipline skill (Phase 11.2 deliverable).

### DR2. Why Δ2 as a NEW test file, not extension of `sc39-pairing-rate.spec.ts`

**Chosen**: NEW file. The existing `tests/integration/sc39-pairing-rate.spec.ts` is **fixture-mode by design** (pipes JSON directly into hook script via `spawnSync`). The Δ2 deliverable is **production-mode** (spawns a child claude process). They test different things:

- Existing: "is the hook script's logic correct?" (script-level correctness)
- Δ2: "is the hook script wired into the harness chain such that real dispatches actually fire it?" (harness-level wiring)

Decision 035 §6 explicitly names the gap and asks for the second one. Conflating both tests in one file would dilute the gap signal and make selective skip-on-Windows messier.

### DR3. R-1 option (c) over (a) + (b)

**Chosen**: option (c) empirical observation. Reasoning matched to E6: lowest friction (~10 LOC of observational analysis), falsifiable (the dispatch.jsonl row format is machine-parseable), and produces a permanent on-disk artifact (the observation md) that 11.5.3's Decision 037 can cite verbatim.

Option (a) requires re-running 10.5.2.A's full diagnostic stash setup — costly and the ephemeral diagnostic scripts were deleted at 10.5.3 close. Option (b) requires a Claude Code "audit my live hook chain" command surface that does not exist in 4.7.

### DR4. Δ3 audit NOT auto-wired into SessionStart

**Chosen**: ship the script + document it in Δ4 skill, but DO NOT add a SessionStart hook entry in `.claude/settings.json`. Reasoning matched to Decision 035 §3.1: any settings.json edit in this session is inert until the NEXT session boot. Wiring Δ3 into SessionStart would not take effect until v2.7. Better to ship the standalone script + let v2.7 author wire it into settings.json with the awareness that the wiring has its own measurement-window dependency.

**Risk**: future-self ships v2.7 forgetting to wire Δ3. Mitigation: Δ4's skill update names Δ3 explicitly + the Phase 11 close-out checklist should add a "wire Δ3 in next phase" item.

### DR5. Test platform-skip strategy

**Chosen**: explicit `it.skipIf(!hasClaudeBin())` + visible `[SKIP]` banner via `console.log`. Reasoning: silent skips on Windows + Git Bash hide regression signal. CI logs must show "this case skipped because no claude in PATH" — that's actionable. A future CI-on-Linux run will re-enable the case and surface failures.

Pattern matches `worktree-isolation.spec.ts:52,63,74` (`it.skipIf(!hasGitOnPath())`).

### DR6. R-2 NOT in this architect leg

**Out of scope**. Decision 035 §5 R-2 (natural volume) is a passive measurement done in 11.5.2 IMPL stage 2 against post-restart, post-volume telemetry. No architect deliverable; the master plan §11.5.2 names it explicitly (`cf21-real-dispatch-sample-v2.6.json`, `unknown-agent-bucket-prevalence-v2.6.json`, `sc39-prereq-volume-v2.6.md`). This architect spec covers ONLY the 11.5.1 architect leg.

Charter alignment: P1 (think before coding) — surface the failure mode rather than retry.

2. **Δ2 production-mode test fails on developer Windows**: child `claude` process spawn is platform-fragile.
