## 2. Open Question #1 Resolution — Mode-B Recovery Mechanism

Master plan §10 Q1: continue-injector vs session-self-reboot for Mode-B recovery.

### Read of the actual scripts

- `scripts/hooks/continue-injector.ps1` (123 LOC):
  - Sends only `continue` + `{ENTER}` to the foreground TUI (line 90–94).
  - **Does NOT touch session state**: same session continues, no `/new`.
  - Has its own idempotency via `.continue-fired-<SessionTag>` marker
    (lines 99–105) — but the SessionTag derives from `.session-ready` mtime, which is
    **session-scoped**, not request-scoped.
  - Designed to be invoked by SessionStart hook of a *fresh* session — using it directly
    after Mode-B truncation (in the SAME session) is a slight repurposing.

- `scripts/session-self-reboot.{sh,ps1}` (sh 53 LOC, ps1 107 LOC):
  - Sends `/new` + `{ENTER}` (ps1 lines 98–100; sh line 31 osascript / line 44 xdotool).
  - Closes current session, starts fresh — **destroys live context**.
  - Fresh session's SessionStart hook then auto-injects `continue` (the design noted at
    ps1 lines 93–97).
  - Cost: ~12K of context-restore tokens (re-load CLAUDE.md, checkpoints/latest.md,
    current-execution.md) but **guarantees fresh budget** if old session was already
    near cliff.

### Decision (binding for 5.1.3 implementer)

**Two-tier strategy. Read-the-real-tokens THEN dispatch.**

```
read REAL = cat $LOG_DIR/.transcript-tokens   # written by budget-watchdog.sh:97
if REAL >= ORCH_WIND_DOWN_TOKENS (200000):
    use session-self-reboot (fresh budget needed anyway)
else:
    use continue-injector (cheaper, preserves context)
```

**Rationale** (validated against scripts):
1. continue-injector is cheaper (~0 context cost) and PRESERVES the session, so the LLM
   can use the partial work it already did before truncation. This is the documented
   manual recovery in `agent-notes.md:122-130`.
2. If the API truncated AT or above wind-down already (which Phase 2 H-11 likely was —
   no `.transcript-tokens` reading is recorded for that event but the session was
   ~mid-Phase-2 and likely large), dispatching `continue` may push the same session past
   cliff with no recovery. session-self-reboot avoids that.
3. Both scripts are **already** on disk. No new mechanism invented.

**Idempotency**: marker `.api-truncation-recovery-fired-<request_id>` (request-scoped,
NOT session-scoped — same session can have multiple distinct truncations from different
API requests). See §3 Task 5.1.3 G subsection for full marker contract.

**Edge case**: when `request_id` is unparseable (`API_REQUEST_ID==""` in
autonomous-stop-watchdog.sh:67 — which currently happens in ~30/33 historical events
because the request_id grep only matches when transcript contains literal `req_*` token,
which is not always present). In that case the marker degrades to `.api-truncation-recovery-fired-<session_id>-<TS_MINUTE>` — coarser but still bounded. Implementer
must validate against historical log entries that have `request_id=none`.

#### C. Behavior contract

For `tool-call-first-lint.sh`:
1. Reads stdin JSON; if `transcript_path` missing or file does not exist, exit 0 silent.
2. Verifies `current-execution.md` exists and has `**autonomous_mode**: true` — same
   pattern as autonomous-stop-watchdog.sh:23-29. If not autonomous, exit 0 silent.
3. Reads the last 32 KiB of the transcript JSONL (large enough for one full turn even
   with tool_result blocks; small enough to be fast).
4. Locates the LAST completed assistant turn (the most recent `.type=="assistant"` block
   whose successor is a `user` or `tool_result` block, OR the file-tail if it is the
   most recent block at end of stream).
5. For that turn's content blocks: if there exists a `text` block matching the verb
   regex AND there does NOT exist a `tool_use` block in the SAME turn → Mode-A suspected.
6. Mode-A suspected → emit_warning to stderr (visible to user via Stop hook stderr
   path) AND append a structured line to `.tool-call-first-lint.log`.
7. **v1 exit code is always 0** — the lint is advisory. v2 may upgrade to exit 2 once
   false-positive rate is measured below 5% over 100+ turns. Document this in the file
   header.
8. On any internal parse error, log `parse_error=...` to lint log and exit 0. Never
   block the parent hook chain.

For `tool-call-first.spec.ts`: 6 tests, each runs the lint against a fixture transcript,
asserts exit code + stderr/log tail content.

New block (insert after line 105, before final `exit 0`):

```bash
# === Phase 5.1 Mode-B auto-recovery (SC-2) ===
# Trigger: API_ERROR_HIT=suspected AND no recovery-fired marker for this request_id.
# Strategy: read .transcript-tokens; choose continue-injector vs session-self-reboot.
# Idempotency: marker file per request_id (or per session+TS-minute when request_id unknown).

if [[ "$API_ERROR_HIT" == "suspected" ]]; then
  RECOVERY_KEY="${API_REQUEST_ID:-${SESSION_ID:-unknown}-$(date +%Y%m%d%H%M)}"
  RECOVERY_MARKER="$LOG_DIR/.api-truncation-recovery-fired-$RECOVERY_KEY"
  if [[ ! -f "$RECOVERY_MARKER" ]]; then
    # Read real tokens; fall back to 0 if file missing/unparseable.
    REAL_TOK="$(tr -d '[:space:]' < "$LOG_DIR/.transcript-tokens" 2>/dev/null || echo 0)"
    [[ "$REAL_TOK" =~ ^[0-9]+$ ]] || REAL_TOK=0
    WIND_DOWN="${ORCH_WIND_DOWN_TOKENS:-200000}"

    # Decide tier: under wind-down → continue-injector (cheap); at/over → reboot (fresh).
    if (( REAL_TOK >= WIND_DOWN )); then
      RECOVERY_MODE="reboot"
      RECOVERY_CMD=( bash "$PROJECT_DIR/scripts/session-self-reboot.sh" )
    else
      RECOVERY_MODE="injector"
      # Windows-only injector at present; sh wrapper emits a warning on non-Windows.
      if [[ -f "$PROJECT_DIR/scripts/hooks/continue-injector.ps1" ]] && command -v powershell.exe >/dev/null 2>&1; then
        RECOVERY_CMD=( powershell.exe -ExecutionPolicy Bypass -File "$(cygpath -w "$PROJECT_DIR/scripts/hooks/continue-injector.ps1" 2>/dev/null || printf '%s' "$PROJECT_DIR/scripts/hooks/continue-injector.ps1")" )
      else
        RECOVERY_CMD=( bash "$PROJECT_DIR/scripts/session-self-reboot.sh" )
        RECOVERY_MODE="reboot-fallback"
      fi
    fi

    # Write marker FIRST (before dispatch), so concurrent watchdog fires lose the race.
    mkdir -p "$LOG_DIR"
    {
      printf 'fired_at=%s\nrequest_id=%s\nsession=%s\nreal_tokens=%s\nmode=%s\n' \
        "$TS" "${API_REQUEST_ID:-none}" "${SESSION_ID:-unknown}" "$REAL_TOK" "$RECOVERY_MODE"
    } > "$RECOVERY_MARKER"

    # Dispatch in detached background so the Stop hook returns fast (< 100ms).
    HANDOFF_LOG="$PROJECT_DIR/agent-workspace/memory/handoff-logs/api-truncation-recovery-$(date +%s)-$RECOVERY_KEY.log"
    mkdir -p "$(dirname "$HANDOFF_LOG")"
    ( nohup "${RECOVERY_CMD[@]}" >> "$HANDOFF_LOG" 2>&1 & ) </dev/null

    # Append a louder log entry into the API alert log for forensics parity with line 99-105.
    {
      printf '[%s] AUTO-RECOVERY FIRED. session=%s request_id=%s real_tokens=%s mode=%s marker=%s\n' \
        "$TS" "${SESSION_ID:-unknown}" "${API_REQUEST_ID:-unknown}" "$REAL_TOK" "$RECOVERY_MODE" "$(basename "$RECOVERY_MARKER")"
    } >> "$LOG_DIR/.autonomous-api-error-alert.log"
  fi
fi
# === end Phase 5.1 Mode-B auto-recovery ===
```

#### G. Idempotency contract

- **Marker name**: `.api-truncation-recovery-fired-<key>` where `<key>` is:
  - `request_id` (e.g. `req_011CaBC123`) when parseable from transcript;
  - `<session_id>-<YYYYMMDDHHMM>` when request_id absent (1-minute coarsening).
- **Location**: `agent-workspace/memory/`.
- **Lifetime**: persistent — never auto-cleaned (10-year scale; admin can prune via
  `find ... -mtime +30 -delete` but no automation mandated). Marker disk-cost negligible
  (one ~80-byte file per real Mode-B event; historical worst-case = 33 events / 7h).
- **Concurrency safety**: marker is written via `> "$RECOVERY_MARKER"` (truncating
  redirect, atomic on POSIX). Two concurrent watchdog fires both call this and one
  wins; the LOSER's marker write is a no-op (idempotent overwrite of same content). The
  RACE is in the dispatch step — two concurrent fires might both spawn a recovery
  command. Mitigation: marker is written BEFORE the spawn, AND the marker check is
  inside the same `if` branch. The remaining race window is microseconds; in practice
  Stop hooks fire serially so concurrent fires are non-existent. **Document the residual
  race in script header**; do NOT add `flock` (file locking is not portable to Windows
  bash).
