## 2. Open-Question Resolutions (Decision 018 binds; recorded here for explicit reference)

### Q1 — Field naming convention: `worktree_isolation` (snake) or `worktreeIsolation` (camel)?

**Decision: `worktreeIsolation` + `baseBranch` (camelCase, matching existing
profile.ts convention).** Decision 018 §2 names the YAML key as
`worktree_isolation`; profile.ts uses camelCase TS field names exclusively
(maxConcurrentSessions, autoHandoff, langfuseEnabled, gracefulEndTimeoutMs).
Adopting camelCase TS keeps profile.ts internally consistent.

> **Recorded as Decision-D-6.3-FIELD-NAMING** (decisions/021-6.3-field-naming.md
> if needed; otherwise inline-only). Rationale: camelCase wins because (a)
> profile.ts has 12+ camelCase fields and 0 snake_case, (b) zod accepts the
> field name verbatim from YAML — operators write `worktreeIsolation:` in YAML
> exactly as in TS, (c) matches reusability-rules.md §"camelCase TS interfaces".

### Q2 — Column naming in Prisma: `worktree_path` (snake) or `worktreePath` (camel)?

**Decision: `worktreePath` (camelCase Prisma field name; Prisma maps to a
snake_case-or-camel column in SQLite — irrelevant since the model is the only
consumer).** Existing schema.prisma uses camelCase Prisma fields exclusively
(`projectId`, `sessionKey`, `claimedBy`, `claimExpiresAt`, `dedupKey`). Master
plan SC-25 text says `Session.worktree_path TEXT NULL` — that is the SQL
column-level shape. The Prisma model field is `worktreePath`.

> **Recorded as Decision-D-6.3-COLUMN-NAMING**. The migration's SQL emits
> `worktreePath TEXT` (matching Prisma's default name-mapping to identical
> camelCase identifier when no `@map` directive is provided).

### Q3 — Worktree path location: `.git/worktrees/orch-<sessionId>/` or sibling-of-rootPath?

**Decision: `.git/worktrees/orch-<sessionId>/` (inside the project's .git
directory).** Decision 018 §3 says the dispatcher records the path; the
master plan §1 SC-25 verbatim says "`.git/worktrees/orch-<sessionId>/`". This
is git-native (linked worktrees). Sibling layout would force users to manage
two top-level dirs per project; .git/worktrees keeps everything in one tree.

### Q4 — Branch model when `worktreeIsolation: true`?

**Decision: `<baseBranch>-orch-<sessionId>` ephemeral branch, deleted on
prune.** Decision 018 §4. The base branch comes from profile field
`baseBranch` (default `main`). The branch is created with `git worktree add`
in one shot and deleted after prune via `git worktree remove --force` +
`git branch -D <branchName>`.

### Q5 — Failure mode: worktree creation fails — abort spawn or fall back to non-isolated?

**Decision: ABORT spawn with a typed error (`WorktreeCreateError`, new domain
error subclass).** Karpathy P2 simplicity: surface failure loudly. Fallback
would silently invalidate the user's opt-in. Operators see a clear error and
can either fix git state or set `worktreeIsolation: false`. The error is
propagated as a `RuntimeSpawnError` subclass to keep the existing exit
classification surface.

### Q6 — Idempotent terminate: what if the worktree path is already gone?

**Decision: terminate() catches `git worktree remove` non-zero exit and logs
warn but does NOT throw.** Mirrors the existing ESRCH handling in
`ClaudeCodeAdapter.terminate()` (claude-code-adapter.ts:454-462). The session
process is already gone; the worktree being already removed is a benign
double-cleanup (e.g., session-start-bootstrap.sh sweep raced ahead).

### Q7 — Concurrency budget interaction: does `worktreeIsolation: true` raise the per-project max?

**Decision: NO. `maxConcurrentSessions` cap (currently `.max(8)` per
profile.ts:185) is unchanged.** Decision 018 §5 binds. v2.1 does not raise
the cap; that is a v2.2 candidate (see Phase 5 carryforward list).

## 3. Architecture Overview — Adapter-Owned Worktree Lifecycle

```
┌─────────────────────────────────────────────────────────────────┐
│  SessionManager.executeSession()  (deterministic dispatcher)    │
│      │                                                           │
│      │  reads profile.worktreeIsolation + profile.baseBranch    │
│      │  via registry.getProjectSync(projectId)                  │
│      │                                                           │
│      │  passes SpawnConfig{ profile, prompt, workdir,           │
│      │       worktreeIsolation, baseBranch, sessionId } to:     │
│      ▼                                                           │
│  ClaudeCodeAdapter.spawn(config)  ──── if worktreeIsolation: true
│      │                                  ┌──────────────────────┐
│      │ 1. createWorktreeIfNeeded(config) ──→ git worktree add │
│      │       cwd = .git/worktrees/orch-<sessionId>/             │
│      │       branch = <baseBranch>-orch-<sessionId>             │
│      │ 2. config.workdir := worktreePath  (override)            │
│      │ 3. record handle.worktreePath into RuntimeHandle         │
│      │ 4. execa('ccs', ..., { cwd: worktreePath })              │
│      │                                                           │
│  ClaudeCodeAdapter.terminate(handle, reason)                    │
│      │ 1. SIGTERM → wait → SIGKILL (existing logic)             │
│      │ 2. cleanupWorktreeIfPresent(handle)                      │
│      │       git worktree remove --force <path>                 │
│      │       git branch -D <branchName> (ignore non-zero)       │
│      ▼                                                           │
│  SessionManager updates DB Session.worktreePath = NULL          │
│       (or leaves NULL if isolation was false from the start)    │
└─────────────────────────────────────────────────────────────────┘

  Orphan recovery (separate from request flow):
  scripts/hooks/session-start-bootstrap.sh  on SessionStart
      → list .git/worktrees/orch-* dirs
      → query DB for ACTIVE sessions with matching worktreePath
      → for each unmatched dir: git worktree remove --force <path>
```

Layer assignment (architecture.md §Layer 3):
- **Layer 1 (Domain)**: `RuntimeHandle.worktreePath?: string` field added
  (read-only domain shape). `SpawnConfig.worktreeIsolation?: boolean` and
  `SpawnConfig.baseBranch?: string` added. NO framework deps; pure types.
- **Layer 2 (App services)**: `SessionManager` reads profile fields, populates
  SpawnConfig, persists `Session.worktreePath` via `OrchStoreService`.
- **Layer 3 (Adapters)**: `ClaudeCodeAdapter` owns ALL `git worktree` shell
  invocations (via execa). The worktree-create + worktree-remove helpers are
  private methods on the adapter. **No other module shells out to git.**
- **Hooks layer (separate)**: `session-start-bootstrap.sh` performs the
  orphan sweep — same git CLI, but driven from the bootstrap context, not
  from any domain code.

I-12 adapter failure isolation: all git invocation errors are caught at the
adapter boundary and wrapped in `WorktreeCreateError extends RuntimeSpawnError`
(spawn-side) or logged-only (terminate-side, idempotent semantics).

I-1 daemon-dumb: zero LLM calls anywhere. All worktree operations are
deterministic git CLI invocations.
