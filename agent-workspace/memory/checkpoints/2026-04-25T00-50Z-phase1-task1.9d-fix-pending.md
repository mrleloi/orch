### Blocker 1 — Lock leak at `session-manager.ts:319`
**File**: `packages/core/src/modules/sessions/session-manager.ts`

**Bug**: In `executeSession()` around lines 303-327:
```
line 303: const locked = await this.store.acquireSessionLock(...)
line 308: if (!locked) throw new SessionLockHeldError(...)
line 319: const sessionRecord = await this.store.createSession(...)  // OUTSIDE try
line 327: try { ... } finally { releaseSessionLock(...) }
```

If `createSession` at line 319 throws (DB error, unique violation, schema mismatch), execution exits before the `try` block begins — the `finally` never runs — the DB lock is held for LOCK_TTL_SECS (60s).

**Fix**: Move the `try` block to begin IMMEDIATELY after the `acquireSessionLock` success check (right after line 308/312, wrapping `createSession`). Ensure the `finally` at line 403 still fires for all paths where the lock was acquired. Add a test that mocks `store.createSession` to reject while lock acquired — assert `releaseSessionLock` IS called.

**Affected lines**: 357, 416, 455, 498, 537 — all use `await new Promise(r => setTimeout(r, 20))` to wait for async spawn chain to populate active map.

Prefer deterministic primitives over time-based waits. Verify tests still pass with no flakes.
