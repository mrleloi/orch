# Decision 024 — Citation Linter `--rollup <path>` Flag (and: linter must be CREATED)

## Context — Critical Correction

The Phase 7 master plan §5.7 references `scripts/utilities/citation-linter.ts` as if it were an existing tool that 7.4 would extend with a `--rollup` flag. **It does not exist.**

7.0.1 research-scanner live evidence:

```
CMD: ls scripts/utilities/citation-linter.ts
RESULT: NOT_FOUND

CMD: grep -rln "citation" packages/cli/src/ scripts/ 2>/dev/null
RESULT: scripts/utilities/build-subagent-index.sh (citation = memory-file mentions, NOT a linter)
```

The actual citation linter is an **inline function** at `tests/integration/feedback-loop.spec.ts:98-109`:

```typescript
function lintRecommendationsCitations(recsMd: string): { violations: string[] } {
  const violations: string[] = [];
  const lines = recsMd.split('\n');
  let currentSection = '';
  for (const line of lines) {
    if (line.match(/^## /)) currentSection = line;
    if (line.match(/^- \*\*/) && !line.includes('cites rollup row:')) {
      violations.push(`${currentSection}: ${line.slice(0, 80)}`);
    }
  }
  return { violations };
}
```

11 lines. One caller (the test itself). Not a CLI. Not invoke-able from the Agent surface.

Therefore 7.4 closes SC-35 in TWO steps:

1. **CREATE** `scripts/utilities/citation-linter.ts` — extract the inline function, wrap a CLI entry, become single-source-of-truth.
2. **EXTEND** with `--rollup <path>` flag for component-existence verification against rollup output.

## Decision

Create `scripts/utilities/citation-linter.ts` as a new standalone CLI. Use **`--rollup <path>` flag** (option a from 7.0.1 survey), NOT a subcommand.

### CLI shape (binding for 7.4.1 IMPL)

```bash
# Mode 1 (default) — lint a recommendations markdown for citation presence
pnpm tsx scripts/utilities/citation-linter.ts --recs <path/to/recs.md>

# Mode 2 — also verify each cited component_type::component_name resolves to an on-disk file
pnpm tsx scripts/utilities/citation-linter.ts --recs <path/to/recs.md> --rollup <path/to/component-rollup.md>

# Optional helper
pnpm tsx scripts/utilities/citation-linter.ts --help
```

**Exit codes**:
- `0` — zero violations
- `1` — ≥1 violation (missing-citation OR — when `--rollup` given — missing-component-existence)
- `2` — usage error (missing required flag, file ENOENT)

**Output (stderr on violation)**:
```
[citation-linter] FAIL: 2 violations
  ## Routing recommendations: - **Tier-down agent::unknown-agent** (missing "cites rollup row:")
  ## Capacity recommendations: - **Increase concurrency** (cites rollup row: not in component-rollup-phase-6.md)
```

**Stdout**: empty on PASS; one line "OK: 0 violations" on PASS for grep-friendliness.

### Why `--rollup <path>` flag (option a) over subcommand (option b)

Live evidence on existing `scripts/` family conventions:

```
scripts/utilities/rollup-telemetry.ts
  --phase <N>
  --input <path>
  --subagent-index <path>
  --output <path>
```

All `--flag <value>` pairs. No subcommand precedent in `scripts/`.

| Property | `--rollup <path>` (a) | subcommand `rollup <path>` (b) |
|---|---|---|
| Alignment with scripts/ family | YES (matches rollup-telemetry.ts) | NO (would be unique) |
| Grep-ability | `grep -r "\-\-rollup" .` finds all callers | `grep -r "citation-linter rollup"` works but is more sequence-dependent |
| Backwards-compat | Default invocation w/o `--rollup` is the citation-only mode (existing behavior of the inline fn) | Default invocation requires choosing a subcommand → non-trivial migration |
| Flag-parser LOC | Trivial: hand-rolled `process.argv.slice(2)` loop, ~12 lines | Requires Commander or yargs subcommand wiring, ~25-40 lines |
| Extensibility (future flags like `--phase`) | Trivial — add another flag | Requires per-subcommand flag scoping |

Option (a) is consistent with `rollup-telemetry.ts`, simpler, and backwards-compatible.

### Argument parsing approach

Live evidence: `rollup-telemetry.ts` uses hand-rolled `process.argv` parsing (no Commander/yargs/parseArgs). Match that convention. Estimated parser: ~15 LOC.

If 7.4.1 IMPL determines `node:util.parseArgs` is cleaner (Node 18+ stdlib), it MAY use that instead — both produce identical CLI shape. Decision binds the user-facing flag form, not the internal parser library.

### `--rollup` mode semantics

When `--rollup <path>` is given:
- After the standard "every `^- \*\*` bullet must contain `cites rollup row:`" check, additionally:
- For each `cites rollup row: <component_type>::<component_name>` reference in the recs markdown,
- Read the rollup file and verify a row exists with that `component_type` + `component_name`.
- If the rollup file does not contain the cited component, emit a violation: `cites rollup row: not in <rollup_path>`.

This catches hallucinated citations where the analyst names a component that doesn't actually appear in the data. Per 7.0.1 survey, this is the "verify-component-existence" semantic the Phase 7 master plan §SC-35 requires.

### Migration of existing inline caller

`tests/integration/feedback-loop.spec.ts:98-109` becomes:

```typescript
import { lintRecommendationsCitations } from '../../scripts/utilities/citation-linter';
```

The exported function keeps the same signature (`(recsMd: string) => { violations: string[] }`) so the test changes only one line (the import). The CLI entry is a wrapper that calls the function and translates result → exit code.

## Charter Reference

- Karpathy P2 (Simplicity First — `--flag` parser is simpler than Commander subcommands)
- Karpathy P3 (Surgical Changes — extracts existing fn instead of rewriting; net new code is small)
- Reusability rule: linter becomes single-source-of-truth (the inline-fn-at-test-only pattern blocks any non-test consumer)

## Reversibility

HIGH for the new script (it's additive — no existing caller breaks). If `--rollup` semantics need to change in v2.3+, the flag is a single conditional branch in main(). If the file location moves, the inline-test caller is the only import.

MEDIUM for the inline-fn extraction. Reverting requires moving the function back to the test file and removing the script — a 1-commit revert.

## Alternatives Considered

### Option (b) — Subcommand `citation-linter rollup <path>`

REJECTED. Misaligned with scripts/ family. Adds parser overhead without functional benefit. See option-comparison table.

### Option (c) — Boolean flag `--rollup` with implicit path discovery

REJECTED. `--rollup` (no value) would force the linter to guess at a default path (e.g., `agent-workspace/memory/component-rollup-phase-*.md`). Implicit path discovery is fragile across phase numbers and breaks the principle that scripts should be deterministic given explicit args.

### Option (d) — Keep inline function in test file; add a separate component-existence test

REJECTED. SC-35 specifies a CLI flag and integration with rollup output. A test-only check leaves the recommendations linter unusable from the CLI/Agent surface. The inline-test approach was good enough for v2.1 but is the explicit deferred carryforward #9 that v2.2 closes.
