# Decision 023 — dispatch.jsonl Schema and Location

## Context

Carryforward #18 closes SC-27's PARTIAL verdict from 6.4 (real-world parallelism methodology). The current parallelism analyzer (`scripts/benchmarks/sc18-realworld.ts`) uses a file-mtime proxy because no real per-dispatch timestamp data exists. The `agent-workspace/memory/budget-tracker.md` update log captures dispatch events in human-narrative form ("Dispatched 6.3 sandwich-architect (sonnet, bg `add50e0773316cdf4`, ~30K)") but cannot be reliably parsed back into `{dispatched_at_ms, completed_at_ms}` pairs.

7.0.1 research-scanner evaluated two options:
- **(a)** Extend `budget-tracker.md` with an embedded JSONL section after a `<!-- DISPATCH_EVENTS -->` marker.
- **(b)** Create a dedicated `agent-workspace/memory/dispatch.jsonl` file. Append-only. One JSON object per line.

Live evidence:
- `wc -l agent-workspace/memory/budget-tracker.md` → 393 lines (already large; mixing free-form narrative with machine data is fragile).
- `budget-tracker.md` rows are 200-400 chars of pipe-separated narrative — not JSONL-shaped.
- Phase 6 dispatched ~30-50 subagents per session; v2.2 will produce similar volumes. ~250 bytes per dispatch event × 2 events (DISPATCHED + COMPLETED) = ~10-25KB per session of pure event data.

## Decision

Adopt **option (b): dedicated `agent-workspace/memory/dispatch.jsonl`**. Append-only JSON Lines. **One object per dispatch event** (so a normal dispatch produces TWO lines: one DISPATCHED, one COMPLETED).

### Schema (binding for 7.2 IMPL)

```json
{
  "event": "DISPATCHED",
  "dispatch_id": "a8603b26e1f4cfb42",
  "agent_type": "sandwich-verifier",
  "model": "opus",
  "parent_session_id": "session-34-phase6-v2.1-kickoff",
  "bg": true,
  "ts_ms": 1714255800000,
  "outcome": null,
  "tokens_used": null
}
```

```json
{
  "event": "COMPLETED",
  "dispatch_id": "a8603b26e1f4cfb42",
  "agent_type": "sandwich-verifier",
  "model": "opus",
  "parent_session_id": "session-34-phase6-v2.1-kickoff",
  "bg": true,
  "ts_ms": 1714256214000,
  "outcome": "DONE",
  "tokens_used": 95925
}
```

### Field contract

| Field | Type | Required on DISPATCHED | Required on COMPLETED | Description |
|---|---|---|---|---|
| `event` | `"DISPATCHED"` \| `"COMPLETED"` | YES | YES | Discriminator |
| `dispatch_id` | `string` | YES | YES | The agent_id from the Agent tool result; foreign key linking the pair |
| `agent_type` | `string` | YES | YES | sandwich-dev, sandwich-architect, sandwich-verifier, task-implementer, spec-compliance-reviewer, code-quality-reviewer, research-scanner, master-planner, telemetry-analyst, systematic-debugger |
| `model` | `"opus"` \| `"sonnet"` \| `"haiku"` | YES | YES | Tier of subagent model |
| `parent_session_id` | `string` | YES | YES | Main-session UUID, or `"main"` when unknown |
| `bg` | `boolean` | YES | YES | Always `true` per project rule (foreground stalls); kept explicit so violation is detectable |
| `ts_ms` | `integer` | YES | YES | `Date.now()` at the event |
| `outcome` | `"DONE"` \| `"FAIL"` \| `"BLOCKED"` \| `null` | `null` (always) | YES (one of three strings) | Subagent return verdict |
| `tokens_used` | `integer` \| `null` | `null` (always) | `int` if available, `null` if subagent did not report | Subagent token cost from completion block |

### Why dedicated file (option b) over extending budget-tracker (option a)

**Separation of concerns**: `budget-tracker.md` is human-readable session narrative (humans skim it for context recovery). `dispatch.jsonl` is machine-readable event log (parsers and analyzers consume it). Mixing the two means every parser must skip narrative rows and the LLM authoring narrative must avoid corrupting the machine section.

**Parsing simplicity**: `dispatch.jsonl` parsing is a 2-line Node snippet:
```js
const events = readFileSync('agent-workspace/memory/dispatch.jsonl', 'utf8')
  .split('\n').filter(Boolean).map((l) => JSON.parse(l));
```
Or `jq -s . dispatch.jsonl` from the shell. Option (a) requires:
```js
const md = readFileSync('budget-tracker.md', 'utf8');
const after = md.split('<!-- DISPATCH_EVENTS -->')[1] ?? '';
const events = after.split('\n').filter((l) => l.trim().startsWith('{')).map(JSON.parse);
```
Three more brittle steps; sentinel-marker-dependent.

**Log rotation**: At v2.3+ if dispatch volume grows, rotation is `mv dispatch.jsonl dispatch-phase-N.jsonl` — one filesystem op. Mixed-content rotation in budget-tracker would need to extract just the JSONL section while preserving the narrative.

**Write-cost**: Append-only `echo '{...}' >> dispatch.jsonl` from any hook or script. No locking issues for sequential single-session writers. One open-append-close round-trip per event; effectively free.

**Read-cost**: Negligible. 50 events/session × 250 bytes = 12.5KB. Tail-read is O(1) for streaming aggregators; full-read is O(file_size) ~10KB.

### Log rotation policy

DEFER. v2.2 does not need rotation. Per-session size estimate: 50 dispatches × 2 events × 250 bytes = ~25KB/session. Even at 10× v2.2's volume (e.g., a 500-dispatch debugging session), file remains under 250KB. If file exceeds 1MB at v2.3+, rotation script will move to `dispatch-archive/dispatch-YYYY-MM.jsonl` at phase boundaries.

### Capture seam (7.2 architect will design specifics)

Two emit points per dispatch:
1. **DISPATCHED** event: written by the main session at the moment of `Agent` tool invocation. Either via a wrapper around the Agent tool (preferred — a TypeScript helper that wraps the dispatch), or via a SubagentStart hook listener.
2. **COMPLETED** event: written when the subagent's completion block returns. Either via the same wrapper closing the loop, or via a SubagentStop hook listener.

The 7.2 architect spec will choose between the wrapper-helper approach and the hook-listener approach based on what fits the existing dispatch surface in `packages/core/`. Either path produces the same JSONL output; this decision binds only the schema and the location.

## Reversibility

HIGH for schema. The schema is additive: future fields can be added per JSONL line and consumers should ignore unknown keys. Removing a field is a breaking change but the file is overwriteable from session-recorded data if needed.

MEDIUM for file location. Renaming `dispatch.jsonl` → some other path is a global-rename + tooling-update, but only ~4-8 callers exist (the SC-27 benchmark plus any future consumers).

## Alternatives Considered

### Option (a) — Extend budget-tracker.md with `<!-- DISPATCH_EVENTS -->` marker

REJECTED. Mixes human narrative with machine data; brittle parsing; complicates rotation. See "Why dedicated file" above.

### Option (c) — SQLite table in the existing Prisma DB

REJECTED. Out of scope for hardening. Adds a Prisma migration, a domain entity, and a query path for what is fundamentally a sequential append log. The complexity is unjustified vs JSONL. If v2.3+ analytics need JOIN-shaped queries, a Prisma table can be ADDED later as a denormalized index — orthogonal to the canonical event log staying as JSONL.
