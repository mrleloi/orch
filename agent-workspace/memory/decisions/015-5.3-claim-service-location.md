# Decision 015 — QueueClaimService Module Placement

## Problem

The atomic claim service introduced in Phase 5.3.3 operates on `QueueItem`
rows AND is consumed by `SessionManager` when spawning a worker. Two
defensible homes:

- **A**: `packages/core/src/modules/queue/queue-claim.service.ts`
  (sibling to `queue.service.ts`)
- **B**: `packages/core/src/modules/sessions/queue-claim.service.ts`
  (next to the consumer)

## Decision

**A — Lives in `queue/`.** Path:
`packages/core/src/modules/queue/queue-claim.service.ts`

Registered as a provider in `queue.module.ts`; exported from the module's
public barrel (`queue.module.ts` exports list); imported by
`sessions.module.ts` via standard NestJS module dependency.

## Rationale

1. **Domain ownership trumps consumer locality.** `QueueClaimService`
   operates on `QueueItem` rows — that is queue-domain logic. Placing it
   in sessions/ would make sessions/ a domain co-owner of queue rows,
   violating architecture.md Layer 2 ("modules talk via public services,
   not by reaching into each other's data").
2. **Consumer/producer separation.** SessionManager is the consumer; it
   calls `queueClaim.claim(workerId, itemId)` to win a queue item before
   spawning. The producer (queue/) owns the row contract; the consumer
   (sessions/) treats it as a public API surface.
3. **Karpathy P3 (Surgical Changes).** queue/ already houses
   `QueueRepository` + `QueueService`. Adding `QueueClaimService` is a
   1-line addition to `queue.module.ts` providers list. Adding it to
   sessions/ requires creating new wiring boilerplate and pulling
   QueueRepository as a cross-module dependency (worse).
4. **Future extensibility.** When QueueItem gains additional state
   transitions (e.g., `release()` to undo a claim), they will be added to
   the same QueueClaimService — at home in queue/, not pulled awkwardly
   into sessions/.

## Affected files

- `packages/core/src/modules/queue/queue-claim.service.ts` (NEW, 5.3.3)
- `packages/core/src/modules/queue/queue.module.ts` (extend providers
  array — 1 line)
- `packages/core/src/modules/sessions/sessions.module.ts` (import
  `QueueModule` if not already — likely already imported)
- `packages/core/src/modules/sessions/session-manager.service.ts`
  (consumer — DI-inject `QueueClaimService`)
