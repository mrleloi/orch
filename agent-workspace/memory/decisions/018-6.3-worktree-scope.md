# Decision 018 — Worktree Isolation Scope

## Problem

Decision 014 deferred worktree isolation to v2.1. Phase 6.3 activates it.
Open questions: (a) which layer owns worktree lifecycle? (b) is it opt-in
or default? (c) does it require schema migration?

## Decision

1. **Lifecycle owner**: `IAgentRuntime` adapter (specifically `ClaudeCodeAdapter`).
   Worktree create/prune happens on `spawn()`/`terminate()`. The dispatcher
   (deterministic code in `packages/core/src/modules/sessions/`) only knows
   "this session has a working directory `cwd`"; the adapter resolves it.
2. **Default**: opt-in via profile field `worktree_isolation: bool` (default
   `false` for backward compat with v2.0 single-main-session model).
3. **Schema**: NEW `Session.worktree_path TEXT NULL` column (Prisma migration).
   When `worktree_isolation=true`, dispatcher records the path; adapter prunes
   on session-end via stored path.
4. **Branch model**: each worktree pinned to `<base_branch>-orch-<sessionId>`
   ephemeral branch; deleted on prune. Base branch comes from profile field
   `base_branch` (defaults to `main`).
5. **Concurrency budget**: same-project `max_concurrent_sessions` cap
   continues to use the existing `.max(8)` schema bound (decision 013).

## Charter Reference

- §3 same-project parallelism (the StockForge-on-day-of-heavy-prompting
  use case in retrospective §6.3).
- I-12 adapter failure isolation (adapter owns its own resource cleanup).
- Karpathy P3 surgical changes (one Prisma migration, one schema field,
  one adapter method pair).

## Consequences

- Enables: same-project N-way parallel sessions (true SC-8 closure).
- Requires: git worktree availability (always present in modern git ≥2.5).
- Failure mode: orphan worktrees if daemon crashes mid-session — addressed
  by SessionStart hook sweep (v2.1 deliverable in 6.3.5).

## Reversibility

Moderate. Schema column is additive (NULL default); profile field defaults
false. Roll-back = drop column + delete adapter methods + remove sweep hook.
