# Decision 014 — Worktree Isolation Deferred

## Problem

True parallel execution of two Claude Code main sessions on the same git
working tree creates mutual file-system contention: simultaneous edits
to overlapping files can cause merge conflicts, lost work, and incoherent
test runs. The clean fix is **per-session git worktrees** — each session
operates on its own checkout under `.git/worktrees/<id>/`.

Master plan SC-8 ("max_concurrent_sessions: 2 across DIFFERENT projects")
explicitly defers worktree isolation per claude-code-learn P3.

## Decision

**v2.0 ships single-main-session + within-session subagent parallelism only.**

Concurrency mechanism in v2.0:
- ONE main Claude Code session per project per host (max_concurrent_sessions
  applies across DIFFERENT projects only — no two sessions on the same
  project simultaneously).
- WITHIN that one session, the LLM dispatches subagents with
  `run_in_background: true` for parallel work. Subagents are isolated by
  their own conversation context — no file-system contention since they
  share a single host writer.

v2.1 adds:
- Per-session git worktrees (`git worktree add .git/worktrees/<id> <branch>`)
- Worktree lifecycle managed by the daemon (create on session spawn, prune
  on session end)
- Profile field `worktree_isolation: bool` (default false in v2.0, true
  in v2.1)

## Rationale

1. **Charter Karpathy P2 (Simplicity First).** Worktree management is a
   non-trivial concern: git worktree state synchronization, branch lifecycle,
   prune-on-crash semantics, IDE integration. Shipping it inside Phase 5
   would balloon the substage budget and risk flaking the v2.0 release.
2. **Within-session subagent parallelism delivers the SC-18 wallclock
   improvement.** The benchmark (5.3.10) measures parallel-vs-serial on
   subagent dispatches — that primitive does NOT need worktrees.
3. **Multi-project concurrency does NOT need worktrees.** Two sessions on
   different projects naturally have disjoint working trees; SC-8's
   `max_concurrent_sessions: 2` is satisfied without isolation work.
4. **claude-code-learn §Subagent Spawn Modes** documents this as P3
   (lower priority than P0/P1/P2 which are absorbed in 5.3.2 — 5.3.10).

## v2.0 limitations (documented for users)

- **Two main sessions on the same project are NOT supported in v2.0.**
  Profile `maxConcurrentSessions: N` for N>1 only takes effect when the
  daemon has multiple distinct projects queued.
- **Subagent file-system contention within a session is the user's problem
  to manage.** The autonomous-protocol's "tool-call-first" + dispatch DAG
  patterns are the v2.0 mitigation.
