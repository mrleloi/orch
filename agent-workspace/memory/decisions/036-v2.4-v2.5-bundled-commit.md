## Context

Per checkpoint #42, v2.4 commit was deferred from session #41 due to harness permission cache for `Bash(git commit:*)`. By session #42, additional Phase 10 substages (10.1 script bug fixes, 10.2 citation-linter dedup, 10.3 CF-DOGFOOD-2 assessment) had staged ~+678 lines / 7 new files on top of the v2.4 staged tree.

Current staged tree at decision time: 101 files, +9183 / -228. Original `.git/COMMIT_EDITMSG_v2.4` describes only Phase 9 substages 9.0..9.8 — its scope no longer matches the staged content.

## Options surveyed

A. **Selective `git reset` and re-stage v2.4-only files; commit v2.4; re-stage Phase 10 files; commit v2.5 separately.**
   - Pros: clean tag history; v2.4 → v2.5 boundary visible.
   - Cons: complex selective staging across ~94 v2.4 vs ~7 Phase 10 files; high risk of mis-staging given .gitignore/CRLF noise; cost in tokens to verify each file's lineage.

B. **Bundle all Phase 9 close + Phase 10 burndown into one v2.5 commit at Phase 10 close.**
   - Pros: simplest path; single commit to verify; phase-10 routing brief already treats v2.5 as the burndown phase covering Phase 9 carryforwards.
   - Cons: no v2.4 tag in git history. The "v2.4" label survives in the in-tree carryforwards-v2.4.md document and decision references; user-facing release versioning is unaffected since this is a single-author repo with no published tags.

C. **Two commits at Phase 10 close: first v2.4 (selective add), then v2.5 (remaining).**
   - Pros: tag history preserved.
   - Cons: same selective-staging risk as A, deferred.

## Decision

**Option B**. Bundle into single v2.5 commit at Phase 10 close.

## Rationale

1. The user's standing grant explicitly authorizes git/release decisions without check-in.
2. v2.x version labels in this project are internal phase markers, not external SemVer; no consumer breaks if v2.4 tag is skipped.
3. Phase 9 close work and Phase 10 burndown are conceptually one effort (Phase 10 = burndown of Phase 9's carryforwards-v2.4.md). Bundling reflects the actual narrative.
4. Selective staging risk (Option A/C) is non-trivial given the file-count and CRLF/.gitignore noise observed in `git status`.
5. I-6 absolute is preserved either way — no commit happens until Phase 10 closes with verifier PASS.

## Consequences

1. `.git/COMMIT_EDITMSG_v2.4` will be REPLACED at Phase 10 close with a comprehensive v2.5 commit message covering Phase 9.0..9.8 + Phase 10 substages.
2. Tag at close will be `v2.5` only (no separate `v2.4`).
3. carryforwards-v2.4.md remains in-tree as historical document; carryforwards-v2.5.md (or equivalent) will be authored by Phase 10's closure substage.
4. If, at Phase 10 close, the user wants v2.4 tagged separately, the decision can be revisited via `git tag v2.4 <staged-tree-hash-prior-to-phase-10>` retroactively — but that requires partial-tree commit which is the same Option A/C complexity. Current default: skip v2.4 tag.

## Application

- Phase 10 close substage MUST author a v2.5 commit message before commit.
