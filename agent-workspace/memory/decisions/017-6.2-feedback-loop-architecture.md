# Decision 017 — Self-Evolution Feedback Loop Architecture

## Problem

Phase 5 SC-6 ships `component-telemetry.jsonl` writer + `subagent-index.md` builder.
Neither is read programmatically — the "self-loop-upgrade" charter §2 promised is
half-delivered. Phase 6.2 must close the read-and-propose half. Question: where
does the LLM analysis live, and what artifacts does it consume/produce?

I-1 (daemon-dumb) forbids LLM calls inside `packages/core/`. The rollup MUST be
deterministic code; the analysis MUST be a worker-side subagent.

## Options Considered

### Option A: Daemon emits raw rollup + master-planner v3 reads it inline at planning time
- Pros: zero new agents; smallest blast radius
- Cons: every master-planner dispatch re-reads ~1,938-line JSONL; cost balloon; no aggregation

### Option B: Two-stage — `scripts/utilities/rollup-telemetry.ts` (deterministic) → `agent-workspace/memory/component-rollup-<ISO>.md` (aggregate stats) → new `telemetry-analyst` subagent reads rollup + emits `phase-N-routing-recommendations.md` consumed by master-planner v3
- Pros: clean separation (deterministic aggregation vs. LLM proposing); rollup is cacheable; analyst is opt-in (only run at phase boundaries)
- Cons: one more agent file; requires master-planner v3 prompt update

### Option C: Hook-driven analysis (LLM call inside a hook)
- Pros: real-time adaptation
- Cons: violates I-1 (LLM in daemon-side code path); rejected outright

## Decision

**Option B** — two-stage with new `telemetry-analyst` subagent.

Pipeline:
1. `scripts/utilities/rollup-telemetry.ts` reads `component-telemetry.jsonl` +
   `subagent-index.md`, emits `agent-workspace/memory/component-rollup-<phase>.md`
   (table per component_type/component_name with aggregate stats: count,
   success_rate, p50/p99 duration, p50/p99 tokens, top failure_modes).
2. `.claude/agents/telemetry-analyst.md` (new sonnet-tier subagent) reads
   the rollup + master-planner.md current routing rules, emits
   `agent-workspace/memory/phase-N-routing-recommendations.md` (proposes:
   model bumps, agent prunes, parallelization gate adjustments, skill
   refactor flags). NO daemon code modifications proposed.
3. `.claude/agents/master-planner.md` updated to read the recommendations file
   at planning time and cite proposals it accepts.

## Charter Reference

- §2 self-loop-upgrade promise (closes the read-and-propose half).
- I-1 daemon-dumb (rollup is shell/TS; analyst is subagent-side LLM).
- Karpathy P2 (Simplicity First — minimum viable feedback loop; defer
  weekly-cron + auto-actuation to v2.2).

## Consequences

- Enables: data-driven master-planner routing (sonnet vs opus per task shape).
- Precludes (intentionally for v2.1): auto-actuation (analyst only proposes;
  human/master-planner curates). Auto-actuation deferred to v2.2.
- New agent count: +1 (`telemetry-analyst`).

## Reversibility

Easy. Rollup script is pure aggregation; analyst is opt-in. Removing both
restores Phase 5 status.
