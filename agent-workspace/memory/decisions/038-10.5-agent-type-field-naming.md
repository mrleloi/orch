# Decision 038 — agent_type field name in dispatch sidecar (SC-39 Case γ)

## Context

Phase 10.5 code-quality review (10.5.2.C) flagged that the sidecar JSONL written by
`dispatch-jsonl-recorder.sh` uses `agent_type` as the field name for the subagent role
(e.g., `"task-implementer"`), while `tool_input.subagent_type` is the upstream field name
in the Claude Code Agent tool payload. A maintainer auditing the hooks in isolation may
not find the rationale for this field-name divergence.

## Decision

Keep **`agent_type`** as the canonical field name in `dispatch.jsonl` and the sidecar
`.dispatch-pending-*.jsonl` files.

Rationale:
- **Decision 023** defined the `dispatch.jsonl` schema with `agent_type`. Renaming it
  would be a breaking change for all existing consumers (sc18-realworld.ts,
  loadTaskFinishRecordsFromDispatchJsonl, etc.).
- **IMP-1** (architect spec 10.5 Part B, §IMP — implementation notes) deferred a rename
  to `subagent_type` on the grounds that schema stability outweighs naming symmetry with
  `tool_input.subagent_type` at this stage.
- The divergence is intentional and cross-referenced in inline comments at:
  - `scripts/hooks/dispatch-jsonl-recorder.sh` (sidecar write lines, PreToolUse + PostToolUse)
  - `scripts/hooks/component-telemetry.sh:194` (SubagentStop sidecar lookup)

## Future

If a v2.3+ schema version bump is warranted, `agent_type` → `subagent_type` rename can
be done atomically across the JSONL files + consumers with a migration script. Decision 023
is the authoritative schema ref; this decision extends it with the IMP-1 deferral rationale.
