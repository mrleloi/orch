### Mandate E — Incremental write for large files (>200 LOC accumulated content)
**Trigger**: any architect document accumulating >200 LOC of in-memory content before being persisted to disk.

**Required pattern**: write the file header + section skeleton FIRST (a single `Write` call with all section headings and placeholder content), then APPEND each section's full content via separate `Edit` passes — one `Edit` per major section.

**Rationale**: Phase 6 task 6.5.3 stalled at ~647 in-memory lines before persisting Deliverables 2-4; only Deliverable 1 (the header block) landed on disk. Incremental write ensures that even on stall or mid-task truncation, downstream agents inherit a coherent partial document rather than an empty or missing file. Every section landed by an `Edit` is recoverable; a single giant deferred `Write` is not.

**Do NOT**: accumulate the entire document in-memory and emit one giant `Write` at the end of the session. This is the 6.5.3 failure pattern.
