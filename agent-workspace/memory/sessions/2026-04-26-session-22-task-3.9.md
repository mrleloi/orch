# Session 22 — 2026-04-26 (Task 3.9)

## Goal

Close the production gap in Task 3.9 Langfuse Backend Toggle: the `bootstrapTracing()` factory
and its 3-way exporter branching were pre-landed in session #19, but `tracing-bootstrap-startup.ts`
never passed `ORCH_TRACE_BACKEND` / `LANGFUSE_*` env vars through to the call site. The toggle
was dormant — the daemon always used the `'otlp'` branch regardless of env.

## Session Type

FOCUSED_IMPL

## Approach

1. Extracted a pure exported function `readBootstrapOptsFromEnv(env, packageVersion)` from the
   module-level side-effect call in `tracing-bootstrap-startup.ts`. This function reads all 5
   relevant env vars and returns a complete `BootstrapTracingOpts`. The module-level call was
   replaced with `bootstrapTracing(readBootstrapOptsFromEnv(process.env, readPackageVersion()))`.

2. The `exactOptionalPropertyTypes: true` strict mode required using conditional spreads for the
   optional Langfuse fields rather than passing `undefined` directly — mirroring the pattern
   already used in `tracing-bootstrap.ts:194`.

3. Added 4 unit tests in `tracing-bootstrap-startup.spec.ts` exercising the pure function for
   all 3 backend values + the missing-keys throw path.

4. Added 3 integration smoke tests (`__e2e__/trace-backend-bootstrap.integration.spec.ts`)
   each running the full bootstrap→span→shutdown lifecycle for one backend value, using
   closed-port endpoints (no real network, I-13 satisfied).

5. Amended `decisions/005-trace-backend-toggle.md` to document the startup-wiring closure.
