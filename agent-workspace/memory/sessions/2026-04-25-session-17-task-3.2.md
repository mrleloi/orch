Implement Task 3.2 — Context-Full Detector: a deterministic per-session token accumulator
that observes `gen_ai.usage.input_tokens` via OTEL SpanProcessor, emits

## Approach
Followed the architect plan A1-A9 sequentially. Merged sub-tasks 3+4 (EventBus channels +
SSE envelope additions) as permitted. Key decisions:
- `DEFAULT_THRESHOLDS` constant declared in `config/defaults.ts` (per centralisation invariant)
  and re-exported from `context-budget.constants.ts`.
- `ContextBudgetService.resolveThresholds()` accesses ProjectRegistryService's internal
  `cache` Map synchronously (required by SpanProcessor.onEnd sync contract).
- TracingModule.onModuleInit skips processor registration in test harness (NODE_ENV=test)
  to avoid OTEL global provider state contamination across Jest test suites.
- `@Optional()` on TracingModule constructor allows the module to boot even if
  ContextBudgetModule resolution fails in edge cases.
- `SessionContextNearLimitPayload` and `SessionForceHandoffPayload` got `[key: string]: unknown`
  index signatures to satisfy EventBusService's `redactLogObject(Record<string, unknown>)` call.

## Decisions Made
- Deviation from plan: TracingModule.onModuleInit skips addSpanProcessor in Jest test harness
  (test harness guard added). The integration test (context-budget.integration.spec.ts) creates
  its own NodeTracerProvider directly — this is the cleaner pattern for integration testing.
  The plan's A3 footnote ("If the cast becomes problematic, switch to passing the SpanProcessor
  into bootstrap via a new option") was not needed; the escape hatch approach works in production.
- B1.21 lifecycle test: since TracingModule constructor uses @Optional(), the processor
  may be null in test DI context. The test was updated to handle both cases (null → verify
  forceFlush is callable; non-null → verify it's called on destroy).
