## Deviations from Plan

### Fix A: routing brief path discovery
The plan specified "scan routing brief" without specifying which brief. The script was previously hardcoded to phase-9-routing-brief.md. The rewrite now prefers phase-10 and falls back to phase-9. The acceptance gate says "at least 10.1∥10.2∥10.3 in routing brief" — phase-10-routing-brief.md contains exactly these entries; PAIRS_CHECKED=3 confirmed.

### Fix A: `parallel_safe_with: []` (empty list)
The routing brief entry 10.0 has `parallel_safe_with: []`. The regex `\[([^\]]*)\]` captures empty string; `grep -E '^[0-9]+\.[0-9]+...$'` filters it to nothing; no pair is added. PAIRS_CHECKED counts only pairs with at least one valid peer, not entries — consistent with spec.

### Fix C: GATE_FAIL_COUNT retained
The existing `GATE_FAIL_COUNT` accumulator (used for attestation output and OTEL) was retained as-is. `FAIL_COUNT` is a PARALLEL explicit accumulator that drives the final exit only. This avoids changing attestation output logic while satisfying the "explicit accumulator" requirement.
