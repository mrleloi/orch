## Key decisions

1. **Proximate context extraction**: type/model extraction uses last 300 chars of text before `agentId` on the same line, giving accurate dispatch-sentence matching even on noisy long budget-tracker rows.

2. **Verdict extraction from context**: the script extracts verdict keywords from the line containing `agentId`. This means a line like "...verifier FAIL... Dispatching sandwich-dev agentId XXX" assigns `fail` to the dispatched sandwich-dev. This is a known limitation (the FAIL verdict belongs to the verifier that triggered the dispatch, not the newly dispatched agent). Acceptable for Phase 5 — the index is a starting point for empirical routing, not a perfect record.

3. **≥50 row target**: the plan specifies ≥50 rows "when fed real Phase 0-4 data". Current repo has only 16 unique agentIds across all memory files (budget-tracker.md covers only Phase 3+; Phase 0-2 session logs don't contain agentId citations). The target is aspirational for future sessions where SubagentStop hook events will accumulate via path A. Builder correctly produces all available rows.

4. **settings.json SubagentStop hook**: the SubagentStop block was not written to `.claude/settings.json` because both `Write` and `Edit` permissions for `.claude/settings.json` were denied in this session context (sandbox enforcement). The helper script `scripts/hooks/subagent-stop-logger.sh` is ready. Manual step required: add the SubagentStop block shown in the session plan §E to `.claude/settings.json`.

## Concerns

1. **≥50 row target not met with current data** (16 rows). This is data availability, not a script defect. Forward-looking: once SubagentStop hook is registered (requires manual settings.json edit), future sessions will populate path-A rows. The index will grow organically.

2. **Verdict attribution accuracy**: verdict is extracted from context near agentId, which can misattribute the triggering event's verdict to the newly dispatched agent. Acceptable for Phase 5 heuristic routing but not for precise failure accounting.

3. **settings.json modification blocked**: sandbox permission prevented automatic registration of the SubagentStop hook. Requires user/operator to manually add the block per plan §E.
