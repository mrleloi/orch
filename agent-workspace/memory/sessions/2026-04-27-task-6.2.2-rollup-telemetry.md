## Deviations from Plan

1. **Import approach**: skeleton used `import ... from '../../packages/core/src/telemetry/index.js'`. This fails at runtime because `scripts/` is ESM (`"type": "module"`) but `packages/core/` is CJS. Named ESM imports from CJS require static analysis that Node.js ESM cannot perform. **Resolution**: used `createRequire(import.meta.url)` interop bridge — standard Node.js pattern for cross-module-type imports. I-10 preserved: Zod schema is used internally by `parseTelemetryLine` which the require'd module provides.

2. **Test pattern**: spec uses `shell: true` in `spawnSync('pnpm', ...)` — required on Windows because `pnpm` is a `.cmd` shim, not a bare executable. This is cross-platform safe (works on Unix too).

3. **LOC**: 351 LOC (vs ~280 LOC estimate). The createRequire interop block and inline type definition added ~30 extra lines.

4. **Deliverable path**: generated both `component-telemetry-rollup.md` (task-specified name) and `component-rollup-phase-6.md` (B.1 spec name) — both written successfully.
