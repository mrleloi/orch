## Approach
Built the SSE client on undici fetch + async body iteration. The key design challenge was the reconnect loop's interruptible backoff — initial implementation had a deadlock where `stop()` cleared the setTimeout but left the awaiting Promise unresolved. Fixed by storing the Promise resolver alongside the timer handle and calling it from `stop()`. The 401 → process.exit path needed special handling: mocked process.exit throws in tests, which the retry catch would swallow; solved by wrapping the exit call in try/catch and re-throwing as `UnauthorizedExitError` to bypass the retry logic. Rate limiter uses a sliding-window Map bounded to RATE_LIMIT_MAX_ENTRIES entries per chat (N6 compliance). queue.empty is derived by polling /api/v1/queue on `queue.state_changed` events (the correct proxy since `queue.dequeued` doesn't exist in SSE event types).
