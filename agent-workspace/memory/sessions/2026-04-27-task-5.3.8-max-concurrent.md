# Task 5.3.8 — maxConcurrentSessions Dispatcher Loop (SC-8)

## Summary

Implemented the per-project concurrency cap for session dispatch. Three changes:

1. **Schema hard-cap** (`packages/core/src/domain/profile.ts` line 185):
   ```typescript
   maxConcurrentSessions: z.number().int().min(1).max(8).default(1),
   ```
   Added `.max(8)` — the sanity rail per master plan SC-8 + decision 013.

2. **Dispatcher cap logic** (`packages/core/src/modules/sessions/session-manager.ts`):
   - Added `countActiveForProject(projectId): number` public method — counts in-process active sessions for a given project (pure in-memory, I-1 compliant).
   - Added cap check at the start of `executeSession()`: calls `registry.getProjectSync(projectId)` (new sync method, no microtask overhead), compares `countActiveForProject()` against `profile.maxConcurrentSessions`. If cap reached: emits `queue.dispatch.deferred` event and writes `{ status: 'failed' }` to result box — no lock acquisition, no spawn.
   - Kept `runSession()` non-async to preserve wake-dedup promise identity semantics.

3. **Sync registry lookup** (`packages/core/src/modules/project-registry/project-registry.service.ts`):
   - Added `getProjectSync(projectId: string): Profile | undefined` — direct cache read.
   - Required to avoid adding a microtask flush to the `executeSession` async chain (existing tests use a hardcoded flush-count of 6).

4. **Event channel** (`packages/core/src/modules/events/event-channels.ts`):
   - Added `queue.dispatchDeferred: 'queue.dispatch.deferred'` channel.
   - Added `EventPayloadMap` entry: `{ projectId: string; activeCount: number; cap: number }`.

5. **Integration tests** (`packages/core/src/modules/sessions/concurrency-cap.spec.ts`):
   - 3 unit cases for `countActiveForProject` (returns 0, counts by project, decrements on end)
   - 1 integration case: N=2 cap across 2 projects, 3rd attempt deferred, snapshots every 50ms over 300ms window, assert max ≤ 2
   - 2 zod cases: `maxConcurrentSessions: 9` → safeParse fails; `maxConcurrentSessions: 8` → passes

6. **Existing test fixes** (`packages/core/src/modules/sessions/session-manager.spec.ts`):
   - Added `getProjectSync: jest.fn().mockReturnValue(profile)` to `makeRegistry()` mock.
   - Added `makeRegistry() as never` to 7 error-case tests that constructed `SessionManager` with only 5 args (registry was missing — previously safe because registry was only used in `_handleForceHandoff`, not `executeSession`).
