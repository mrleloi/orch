## Deviations from Plan

1. `setupWorktreeSpawn()` in adapter spec updated to prepend probe mock (call order changed: probe -> git-add -> ccs). T1/T3/T4 assertions updated to account for extra call. This is a required consequence of the lazy-once probe being introduced.

2. T3 (sweep test) uses a custom sweep script with `PATH=/usr/bin:/bin` rather than passing `PATH: ''` to the parent spawnSync. The reason: `PATH=''` makes bash itself unfindable on Windows Git Bash (ENOENT on the bash subprocess). Overriding PATH inside the script (after bash launches) correctly tests the `command -v git` guard without breaking the bash process itself.

3. `tests/hooks/helpers/create-test-db.ts` was added (not mentioned in plan) because `better-sqlite3` is a native module that vite/vitest cannot bundle. The existing pattern (rollup-telemetry.spec.ts) uses `pnpm tsx` subprocess for similar reasons.

4. The `session-active-check.ts` script uses direct `PrismaClient` + `PrismaBetterSqlite3` (same as PrismaService) rather than importing PrismaService (which is NestJS-injectable and requires the DI container). This matches the pattern described in Part B and satisfies I-14.

5. mode-c-guard.spec.ts has a pre-existing intermittent timing failure on Windows ("expected 561 to be less than 500") -- not caused by this task.

## Assumptions Made

1. The sweep test T1 verifies orphan detection via log entries (not actual directory removal), because `git worktree remove --force` on fake (non-git-registered) directories returns non-zero and the `|| true` guard keeps the dir. Log-based verification is the correct behavior contract for the stanza.

2. `WorktreeProbeResult` type is exported from `git-worktree-probe.ts` so `claude-code-adapter.ts` can type the cache field without `any`. The spec plan says "cache the boolean result" but typing as the full result object is cleaner and avoids a separate boolean field.

3. The `worktreeSupportCache` is initialized to `undefined` and typed as `WorktreeProbeResult | undefined` (not `boolean | undefined`) to preserve the reason string for the warn log when probe fails.
