## Architecture Decision: spawnSync vs execa in test layer (OQR-4)

The brief mandated `execa('git', [...])` for I-3. After reading all 18 test files under
`tests/`, the universal established pattern is `spawnSync(cmd, args_array)` from
`node:child_process`. Key findings:

1. `tests/` has no `package.json` — no explicit dependency declaration for execa
2. execa v5 lives in `packages/core/node_modules` (or pnpm store: `node_modules/.pnpm/execa@5.1.1/`)
3. Importing execa in a `tests/` file creates an implicit dependency on pnpm hoisting
4. `spawnSync('git', ['worktree', 'add', '-b', name, path, 'HEAD'])` is equally I-3 safe:
   - No shell interpolation
   - Explicit string array args
   - No `{ shell: true }`
5. The existing integration peer `feedback-loop.spec.ts` uses only `node:child_process`

Decision: use `spawnSync` with array args. This satisfies I-3 at the test layer while
maintaining consistency with 100% of existing test infrastructure. The spec file comment
documents this choice and cites this session note.
