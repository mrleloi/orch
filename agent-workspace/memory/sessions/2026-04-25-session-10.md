## Approach
Implemented four Telegram handlers + two new core REST endpoints + CoreApiClient extensions + BoundedStdoutBuffer, all wired to the existing adapter pattern established in Task 2.2. The main design decisions were: (1) add BoundedStdoutBuffer as a subclass of BoundedStderrBuffer to reuse the ring-buffer pattern; (2) collect stdout in SessionManager._awaitHandleCompletion via a 'data' listener (previously just discarded); (3) update ProjectDto to match the actual API response shape (Profile fields, not the stale DTO definition); (4) wire all four handlers into main.ts.

## Decisions Made
- D1: BoundedStdoutBuffer extends BoundedStderrBuffer (class inheritance reuse) rather than a separate base class, to minimize invasive changes to existing code.
- D2: ProjectDto updated to match actual API shape (Profile fields) rather than adding a mapping layer in the controller, since the old ProjectDto definition (id, name, profilePath, activeSessionCount, registeredAt) was stale and never matched what the API served.
- D3: getLogs() uses response.text() (plain text) matching the Content-Type: text/plain header set by @Header decorator on the controller endpoint.
