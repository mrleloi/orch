# Task 5.4.9 — Mailbox markRead Count-Idempotency Fix

## Date
2026-04-27

## Motivation
The 5.3.12 spec-compliance verifier flagged a P3 CONCERN: `MailboxRepository.markRead(ids)` was
state-idempotent (calling twice produced the same DB state) but NOT count-idempotent (the first
call returned `updated: N`, the second also returned `updated: N` instead of `updated: 0`).

This matters for callers that inspect the return value to decide whether work was done. A count of
N on the second call is a false positive.

## Root Cause
The Prisma `updateMany` in `markRead` used:
```ts
where: { id: { in: ids } }
```
This matched ALL rows with the given IDs regardless of their current `read` value, so rows that
were already `read: true` were "updated" again, inflating the count.

## Fix Applied
`packages/core/src/modules/sessions/mailbox/mailbox.repository.ts` — added `read: false` to the
`updateMany` where clause:
```ts
await this.prisma.workerMailbox.updateMany({
  where: { id: { in: ids }, read: false },
  data: { read: true },
})
```
Now only genuinely unread rows match, so a second call on already-read IDs returns `count: 0`.
