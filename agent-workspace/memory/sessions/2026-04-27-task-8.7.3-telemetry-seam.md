## Deviations from Plan

1. **Test runner is Jest not vitest.** The gate command in the task envelope says `pnpm vitest run packages/core/src/telemetry/sync-seam.spec.ts` but the package uses Jest (`jest` in package.json scripts). Tests were run with `npx jest --testPathPatterns="sync-seam"` which passes. The spec files use Jest syntax (`jest.fn()`, `describe`, `beforeEach`) consistent with the rest of the codebase.

2. **`send()` methods are synchronous `Promise.resolve()` not `async`** for NoOpSink and HttpsNdjsonSink. This satisfies the `TelemetrySink` interface (returns `Promise<void>`) while avoiding the `require-await` ESLint rule. The interface contract is preserved.

3. **Interface field name `_event` vs `_`.** The ESLint `no-unused-vars` rule flags `_` as unused. Used `_event` with an ESLint-disable comment as the idiomatic pattern.

## Assumptions Made

1. Jest (not vitest) is the correct test runner for this package — confirmed from package.json.
2. The `TelemetryEvent` interface uses `timestamp` (Part-B spec) not `ts` (Decision 031 wire format field). Part-B contract takes precedence for the seam's TypeScript surface.
3. `ORCH_TELEMETRY_SYNC` env var reading happens at constructor time (not lazily at emit time). This means the enabled state is fixed at construction — consistent with how `TracingService` and similar services are initialized.
4. Sink error swallowing applies to all errors from `sink.send()`, not just network errors. This aligns with "failures non-blocking" in Decision 031 Consequence 8.
5. `HttpsNdjsonSink` does NOT implement batching, rate-limiting, or exponential backoff in v2.3 — those are v2.4 concerns per the decision. The stub resolves immediately.
