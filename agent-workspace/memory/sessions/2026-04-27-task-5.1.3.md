## Behavior Implemented

Two-tier recovery strategy per architect §2 Q1 resolution:
- `REAL_TOK < ORCH_WIND_DOWN_TOKENS (200000)` AND Windows (`powershell.exe` on PATH):
  use `continue-injector.ps1` (cheap; preserves session context).
- `REAL_TOK >= 200000`: use `session-self-reboot.sh` (fresh budget needed).
- Non-Windows (no `powershell.exe`): fall back to `session-self-reboot.sh` regardless
  of token level (Q3 resolution).

Idempotency key:
- `request_id` (e.g. `req_011CaBC123`) when present in transcript tail.
- `<session_id>-<YYYYMMDDHHMM>` (1-minute coarsening) when request_id absent.

Marker written BEFORE dispatch to close TOCTOU race. No `flock` (not portable on Windows bash).
Dispatch via `( nohup ... & ) </dev/null` — detached background, Stop hook < 100ms.

## R-1 Mitigation (anti-recursion)
Per-request_id marker prevents same-event re-fire. Different request_ids (different
truncation events) each get their own marker — correct behavior. Consecutive truncations
within the same UTC-minute (when request_id absent) share one marker key; that is
conservative but bounded (worst case = one recovery missed if two distinct truncations
happen in the same 60-second window, which is rare).

## R-7 Mitigation (cross-platform)
`command -v powershell.exe >/dev/null 2>&1` gate ensures injector path is Windows-only.
Non-Windows falls through to `reboot-fallback` mode unconditionally. Documented in
script header comments.
