# Session 26 — 2026-04-26 (Task 4.3 Module Shutdown Ordering)

## Goal
Fix MINOR-3: SchedulerService.onModuleDestroy() must await in-flight tick promises before returning, so that no prisma.$transaction() call races against PrismaService.onModuleDestroy() when the DB connection is closed.

## Session Type
FOCUSED_IMPL

## Approach
Added `inFlightTicks: Set<Promise<void>>` to `SchedulerService` to track every tick promise launched by the node-cron callback. The tick callback registers a self-cleaning tracked promise (using a `ref` box to avoid the forward-ref problem with `const`). `onModuleDestroy()` now has three sequential steps: (1) stop all tasks, (2) await all in-flight ticks, (3) unsubscribe event bus. Added two new unit tests (T-SCHED-SD-A and T-SCHED-SD-B) to `scheduler.service.spec.ts` that exercise the in-flight await path and the no-deadlock path respectively.

## Decisions Made
