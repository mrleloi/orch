### Important (should fix before Phase 5.5 / before telemetry hook is shipped wide)

I-1. INV-S9 telemetry hook latency budget violated (P6 / SC-6 quality)
- Evidence: tests/hooks/component-telemetry.spec.ts self-reports [INV-S9] component-telemetry.sh latency n=8 median=567ms p99=2527ms. Architect section 6 INV-S9 target: <50ms p99; absolute cap: 200ms (sync hook deadline).
- Risk: Wired into PostToolUse + SubagentStop + SessionStart, this hook will add ~500ms-2.5s to EVERY tool call. On a 200-tool-use session that is 100s-500s extra wall-clock. Windows bash is the worst case.
- Suggested fix: (a) defer the hook payload to a fire-and-forget background subshell so the hook returns in <50ms regardless; (b) port the hot path to a single tsx/awk pass; (c) document INV-S9 as relaxed-on-Windows and tighten target to <500ms p99.
- Why not blocking: tests pass (harness verifies functional correctness, not latency target - the latency line is logged informationally). The hook IS wired into .claude/settings.json (file shows M in git status). Phase 5.5 should re-test post-wiring before this ships into production hook chain.
- Owner: Phase 5.5 telemetry-rollup task, OR a 5.2.11 surgical fix dispatch if architect closes this before 5.3.
