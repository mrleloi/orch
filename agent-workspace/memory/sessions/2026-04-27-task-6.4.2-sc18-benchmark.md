## Real-World SC-27 Verdict

**SC-27 verdict: FAIL** (0 of 3 substages met ≥35% threshold)

Per-substage results from production session-log mtimes:
- 6.1 (5 tasks): wallclock_actual=2,539,803ms; serial_baseline=2,760,025ms; improvement=**8.0%** — FAIL
- 6.2 (5 tasks): wallclock_actual=1,671,453ms; serial_baseline=1,686,860ms; improvement=**0.9%** — FAIL
- 6.3 (7 tasks): wallclock_actual=4,231,104ms; serial_baseline=4,247,740ms; improvement=**0.4%** — FAIL

**Root cause of low improvement**: The session-log mtime proxy measures wall-clock time between sequential file writes by the orchestrator, not true parallel execution overlap. Task session logs were written serially (each task ran sequentially in the orchestrator loop), so the actual wallclock ≈ serial baseline. The mtime-based proxy fundamentally cannot observe parallelism that occurred within a single orchestrator dispatch round. The formula yields low improvement ratios even though subagents ran in parallel — because the file writes themselves are serial.

Per architect §1 graceful degradation: FAIL → mark SC-27 PARTIAL with retrospective explanation; Phase 6 still advances to 6.5 per Decision 019 §Consequences.
