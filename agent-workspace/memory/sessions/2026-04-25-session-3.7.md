# Session 3.7 — 2026-04-25

## Goal
Implement SchedulerModule: cron-driven plan enqueue for time-based sessions. On daemon boot, register a `node-cron` job for every `(projectId, cronName, cronExpression)` triple in each project profile's `cron:` map. On each tick, call `QueueService.enqueue()` with a minute-bucket dedup key.

## Session Type
FOCUSED_IMPL

## Approach
Executed the session plan top-to-bottom in 8 steps. Added `node-cron@4.2.1` (ships its own TypeScript types — no `@types/node-cron` needed). Extended `ProfileSchema` with zod-validated `cron:` field using `node-cron`'s `validate()` as the refine function. Added `scheduler.*` event channels and payload types. Created `SchedulerService` with hot-reload support via event subscriptions and `SchedulerModule` wired into `AppModule`.

Key discovery during testing: **jest fake timers are incompatible with Prisma transaction timeouts**. Prisma uses `setTimeout` for its 5000ms transaction timeout; advancing the fake clock causes the transaction to expire immediately. Solved by:
1. Unit tests: use `jest.useFakeTimers()` with timezone-agnostic `* * * * *` expressions, valid because `advanceTimersByTimeAsync` properly chains through node-cron's async heartBeat → `onTick` → mock `enqueue`.
2. Integration test: use real timers with `* * * * * *` (every second, 6-field) and a polling wait loop. This is documented in the test file.

Second discovery: `row.payload['dedupKey']` is undefined — `dedupKey` is a top-level `QueueItem` field, not in `payload`. Fixed assertion to use `row.dedupKey`.
