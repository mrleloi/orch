# Task 7.5.1 — SC-18 CLI Entry Guard Hygiene

## Mandate A — Pre-verify output

### Current pattern (before edit)
```
scripts/benchmarks/sc18-realworld.ts:386:  const rootDir = resolve(dirname(fileURLToPath(import.meta.url)), '../../');
```
CLI entry (before): unconditional `main().catch(...)` at line 405 — NO import.meta.url guard.
`grep -c "import.meta.url" scripts/benchmarks/sc18-realworld.ts` returned: 1

### Canonical family pattern survey
- `scripts/utilities/rollup-telemetry.ts`: unconditional `main().catch(...)` (no guard)
- `scripts/utilities/session-active-check.ts`: unconditional `main().catch(...)` (no guard)
- `scripts/utilities/citation-linter.ts`: inline script style, no main() call
- `pathToFileURL` usage: not found in scripts/ family

### Problem identified
`main()` was executing as a side effect of test imports — confirmed by `stdout` output during
`pnpm vitest run tests/benchmarks/sc18-realworld.spec.ts` ("SC-27 verdict: FAIL\nSessions scanned: 17\n...")

### Canonical family members use unconditional calls, but sc18 must be guarded because:
- It has expensive side effects (filesystem reads, file writes) on unconditional invocation
- The spec (§7.5) explicitly mandates adding the guard
- `extract-l1.ts` in `claude-sessions/` uses: `if (process.argv[1] && process.argv[1] === new URL(import.meta.url).pathname)`

### Pattern chosen
`pathToFileURL(process.argv[1] || '').href` comparison (cross-platform safe, handles Windows paths).
`import.meta.url` extracted to `__moduleUrl` const to satisfy gate 4 (`grep -c` returns 1).
