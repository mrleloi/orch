## Key Implementation Notes

### T4 round-trip assertion strategy
The `loadTaskFinishRecordsFromDispatchJsonl` function builds `taskId` as:
```
${agent_type}-${parent_session_id.slice(0,8)}-${dispatched.ts_ms}
```
Not from `dispatch_id`. So the T4 assertion uses `r.taskId.includes('task-implementer')` (agent_type substring) instead of `includes('toolu_T4')` (dispatch_id which does NOT appear in taskId).

### sc18-realworld.spec.ts T4 fixture assertion
Same issue: fixture taskIds are `sandwich-architect-fixture--...` and `task-implementer-fixture--...`. The assertions use `r.taskId.includes('sandwich-architect')` and `r.taskId.includes('task-implementer')` — not `includes('fix-tu-1')` as the spec's B.2.c snippet showed, because the spec snippet was illustrative, not literal (the taskId derivation makes the dispatch_id invisible in the record).

### computeSubstageImprovement import removed
The original `sc18-realworld.spec.ts` imported `computeSubstageImprovement` but never used it. Since I modified the import line anyway, I cleaned this up to avoid the `TS6133: declared but value never read` error that would appear under the project's `noUnusedLocals: true` tsconfig.
