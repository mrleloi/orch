## Wiring Bug Found (Decision-Worthy Finding)

**Bug**: `EventBusService.emit()` applies `redactLogObject()` to the event payload before passing it to EventEmitter2 subscribers. `redactLogObject` (packages/core/src/modules/security/redact-log-object.ts:65-67) treats `Date` objects as plain objects (since `typeof date === 'object'` and `Date` has no own enumerable properties) and reconstructs them as `{}` (empty plain objects). This means any event payload containing `Date` fields loses those fields.

**Impact**: When `SessionManager._handleGracefulEnd` emits `session.ended` with `session.endedAt: Date`, `HandoffOrchestratorService._handleContextFullEnd` receives `session.endedAt = {}` and fails at `(session.endedAt ?? new Date()).toISOString()` with `TypeError: toISOString is not a function`.

**Workaround in test**: For A4, we emit `session.ended` directly on the underlying `EventEmitter2` instance (bypassing `EventBusService.emit` → `redactLogObject`). This is a test-only coupling documented in the A4 test body comment.

**Production status**: This bug exists in production. `handoff-orchestrator.integration.spec.ts` uses a mock EventBus that bypasses `redactLogObject`, masking the bug. In production (real AppModule), every `session.ended` emission via `EventBusService.emit` would cause HandoffOrchestrator to fail with this error.

**Recommended fix**: In `redact-log-object.ts:redactValue()`, add a special case before the generic object branch:
```ts
if (value instanceof Date) {
  return value; // pass through Date objects unchanged
}
```
This is a 2-line production fix in `packages/core/src/modules/security/redact-log-object.ts`. It must be scheduled as a separate narrow-fix task (Task 3.11.1 or 3.11.x) before Phase 4 integration work.
