## Approach
Created `packages/core/src/__e2e__/latency.spec.ts` as a sibling to `round-trip.spec.ts`. Reused the same bootstrap pattern (NestJS test module, PrismaService override, fake IAGENT_RUNTIME, in-memory OTEL provider). Implemented timing via HTTP round-trip measurement (t0 before POST, t1 after HTTP 200 response), with one warm-up POST in beforeAll to prime JIT and Prisma cache.

Key design decision: the original plan called for "EventBus listener resolving a Promise" as the timing signal. During implementation, discovered that having an active EventBus listener during a Fastify HTTP request triggered ECONNRESET in the test environment (EventEmitter2's synchronous dispatch inside the request handler interacted with the OTEL HTTP instrumentation). Instead, used HTTP round-trip time as the timing signal — which is a provably correct upper bound since EventBus.emit() fires synchronously during the request handler (before HTTP response is sent). Documented this deviation in the test file.
