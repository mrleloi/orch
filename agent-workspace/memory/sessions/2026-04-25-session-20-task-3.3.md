## Goal
Implement Graceful Session End: wire the `session.forceHandoff` EventBus event (emitted by ContextBudgetService from Task 3.2) into `SessionManager` to perform a controlled, deterministic session termination with I-6 operator gate preservation.

## Session Type
FOCUSED_IMPL

## Approach
Added `SessionState.Ending` to the state machine, added `writeStdin` to `IAgentRuntime` and `ClaudeCodeAdapter`, extended `ProfileSchema` with `autoHandoff`/`gracefulEndTimeoutMs`/`commands.sessionEnd`, added `EndedReason` enum to `@orch/shared`, implemented `_handleForceHandoff` and `_handleGracefulEnd` in `SessionManager` with onModuleInit subscription, and added `session.handoffPending` to the SSE event channel list. Tests use real timers with short timeouts (50ms) rather than fake timers to avoid async incompatibilities.

## Deviations from Plan
1. **No explicit ENDING state in state transition map**: The plan said "verify the existing transition map allows ENDING from RUNNING; if not, add it". There was no formal transition map table in the code — the state machine is implicit. Added `Ending` state with JSDoc documenting its valid transitions (Ending → Ended, Ending → Failed).
2. **ProjectRegistryService injection**: Plan said to read profile config; required injecting `ProjectRegistryService` into `SessionManager`, which required adding `ProjectRegistryModule` to `SessionsModule` imports.
3. **`withSpan` span parameter**: The existing `withSpan` mock in tests passed `{}` as the span. Updated mock to include `setAttribute`, `addEvent`, etc. to support the `span.setAttribute()` calls in `_handleGracefulEnd`.
