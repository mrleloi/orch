## Deviations from Plan

1. `RuntimeHandle.worktreePath` typed as `string | undefined` (not `string?`) due to
   `exactOptionalPropertyTypes: true` in tsconfig.base.json. With EOP, optional property
   `string?` does not allow explicit `undefined` from a getter that returns `string | undefined`.
   The spec says "optional read-only" — `string | undefined` satisfies that semantically.

2. `resume()` handle object required `worktreePath: undefined` to satisfy the updated
   `RuntimeHandle` interface (required field, not optional). This is a two-line addition
   matching the pattern (not a structural change).

3. Worktree tests use per-test `jest.spyOn(process, 'kill')` instead of a describe-level spy.
   Reason: the outer `describe('terminate')` already has its own KILL_MOCK at describe scope.
   Double `jest.spyOn` on the same function causes ordering issues when `afterAll` restores
   the outer spy before the inner tests run. Per-test spyOn+restore in `finally` is safer.

4. The worktree add execa call was reformatted by eslint `--fix` from single-line to
   multiline (line exceeds printWidth). C.4 still passes with 2 hits (worktree remove +
   branch -D remain single-line).

## Assumptions Made

1. `execa` with `reject: false` returns an object with `exitCode` even on non-zero exit
   (verified by the existing ccs spawn pattern in the adapter).
2. The `worktreeBox` stored in `childProcessMap` persists until `awaitAndClassify` clears
   the map entry — `terminate()` is always called before `awaitAndClassify` in the normal
   lifecycle, so cleanup runs while the map entry is present.
3. The `orchSessionId` derived from `spawn-${Date.now()}` is sufficient uniqueness for
   worktree paths. The spec doesn't require a DB session ID at this point (the DB session
   ID isn't available until after spawn returns).
